# Сайт и личный кабинет FuntiDesk

Публичные файлы сайта находятся в одном каталоге `web/`. Корень содержит интерактивную демонстрацию, `/account/` — настоящий интерфейс кабинета для API `/api/account/v1`. Демонстрационные скрипты не подключаются на странице кабинета.

## Источник сайта

Перенесён только `web/artifact/` из [закреплённого commit](https://github.com/michailr1/FuntiDesk/tree/0344118bcc88a6185b81f701ba9e43d7e8705495/web/artifact). Клиент и сервер из старой ветки не сливались. `SOURCE.json` сохраняет исходные имена, размеры и SHA-256 всех 15 публичных файлов. При read-only сверке 2026-10-13 все 15 URL `https://desk.funti.cc/` совпали с исходным manifest.

После переноса обновлены русские имена демонстрационных устройств, FAQ о семейных правах и видеозвонках, Windows/Android ссылки, команда установки и ссылка portable. Изменён порядок «Постоянного доступа» под одноразовым паролем по текущему клиенту. Демо остаётся локальным: оно не подключается к устройствам и не использует камеру или микрофон.

## Кабинет

- Почта → код, bootstrap и CSRF, выход и выход из всех сессий.
- Устройства и копии семейных списков показываются без подключения, сопряжения и редактирования прав.
- Удаление передаёт ключ выбранного устройства и случайный 256-битный `request_id`. При неопределённом результате запроса повтор использует тот же ID до подтверждённого ответа в текущей странице.
- Журнал показывает подтверждение каждой доставленной команды и ожидание обмена. Списки обновляются кнопкой; последнее время обмена не выдаётся за текущий online-статус.
- Все данные API вставляются через `textContent`. Сессия хранится только в серверной `Secure; HttpOnly; SameSite=Strict; Path=/` cookie. JavaScript хранит CSRF и контекст незавершённого входа только в памяти; bearer-токен в UI и web-storage не появляется.
- Запросы разрешены только с `https://desk.funti.cc`, только в свой API, без редиректов и fallback. Страница имеет отдельную CSP и не загружает сторонние ресурсы.

## Проверка и упаковка

```sh
node --check web/account/account.js
python3 scripts/web/package.py
python3 scripts/web/package.py --output /tmp/funtidesk-web.tar
```

После изменения публичных файлов обновить manifest:

```sh
python3 scripts/web/package.py --write-manifest
```

Архив включает только публичные HTML/CSS/JS/изображения, без README, SOURCE и manifest. Порядок файлов, права и timestamps зафиксированы, поэтому повторная упаковка одних байтов даёт тот же SHA-256. Обычный HTTP-сервер подходит для просмотра демонстрации, но настоящий кабинет намеренно не обращается к API с локального или чужого origin.

Локальные браузерные проверки не заменяют доставку писем во входящие, реальные Windows-клиенты и приёмку на рабочем сервере. Эта ветка не выполняет deploy, изменение Caddy/DNS или отправку писем внешним адресатам. Порядок будущего размещения — `DEPLOYMENT.md`.

Проверка настоящего локального API в Chromium требует Python 3, Node.js, установленный для разработки `playwright` и системный `/usr/bin/chromium`. Сначала собрать account binary, затем:

```sh
node scripts/web/account-browser-test.mjs
```

`FUNTI_ACCOUNT_BINARY` задаёт путь к уже собранному binary; по умолчанию используется `account/target/debug/funtidesk-account`. `FUNTI_WEB_SCREENSHOTS` задаёт необязательный каталог снимков. Проверка создаёт отдельную временную базу и ключ, локальный SMTP-приёмник и тестовый Unix-реестр. Все браузерные запросы перехватываются и направляются только в локальную среду, а тестовые письма остаются в памяти. Для перехода между минутными окнами тест очищает только минутные лимиты своей временной базы; часы, коды и продуктовый сервис не подменяются. Тестовые устройства подтверждают события подписью; это не проверка применения удаления реальной Windows-службой.

Известное ограничение выбранного исходника: mobile-демо ссылается на `/assets/iphone-home.png`, которого нет в исходном manifest. Кабинет не использует этот файл. Неполная синхронизация макета настроек и уведомления обновления с текущим клиентом также остаётся отдельной работой над демонстрацией.
