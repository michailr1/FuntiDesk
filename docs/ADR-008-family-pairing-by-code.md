# ADR-008: Добавление в семью по одному коду

**Статус:** принято владельцем 2026-10-11 (подтверждение на компьютере с кодом — да; срок кода 5 минут; сервер разворачивается после проверки на двух компьютерах). Реализация — ветка `claude/family-pair-code`.
**Связано:** ADR-006 (семейный доступ — дополняет раздел «Сопряжение»), ADR-004 (свой сервер), `docs/ROADMAP.md` («Проще добавлять в семью»), `docs/SECURITY.md`.

## Проблема

Сейчас, чтобы добавить компьютер в семью, на втором компьютере вводят ID первого, код из 6 цифр и имя. ID лишний для человека: его нужно продиктовать вместе с кодом. Решение владельца 2026-10-11: вводят **только код**, компьютер находится по коду на сервере FuntiDesk; код живёт 3–5 минут и подходит один раз. Там же найден дефект: на ноутбуке владельца сопряжение показывало «добавлен», но запись в семье не появлялась.

## Предлагаемое решение

### Сценарий

1. Компьютер А (мама): «Семья» → «Добавить в семью» → «Показать код». На экране — 6 цифр и обратный отсчёт **5 минут**.
2. Компьютер Б (помощник): «Добавить в семью» → одно поле «Код» → «Добавить». Имя заполняется само — имя компьютера А (`minipc`, `desktop-86ud4s7`), его можно поменять.
3. **На А появляется окно «Добавить в семью «Михаил» (440 171 008)?» — «Добавить» / «Отмена».** Человек у А как раз смотрит на экран с кодом.
4. Обе стороны сохраняют друг друга, как сейчас (ADR-006: ключи устройств, взаимно).

### Сервер (hbbs, наша сборка — ADR-004)

- А, показывая код, регистрирует его на сервере: сообщение `FuntiPairOffer { id, code, подпись ключом устройства А }`. Сервер проверяет подпись ключом, который А уже зарегистрировал для своего ID, и хранит «код → ID» **5 минут**, в памяти, не на диске. Новый код от А заменяет старый.
- Б отправляет `FuntiPairLookup { code }` и получает ID компьютера А. После первого успешного поиска код у сервера удаляется (одноразовый).
- Ограничение попыток: с одного адреса не больше 5 поисков в минуту и 30 в час; после этого — отказ до конца окна. Неверный код и истёкший код — один и тот же ответ «код не найден».
- Сообщения — в `rendezvous.proto`, номера от 1000 (`RendezvousMessage`), по уже зашифрованному соединению с сервером (`secure_tcp_required`).

### Защита

- **Подтверждение на А** — главная защита. Перебором кода на сервере можно в лучшем случае узнать ID компьютера, который сейчас показывает код, но добавиться без «Добавить» на его экране нельзя. Это же закрывает риск «сервер или тот, кто его захватил, сам добавляется в семью».
- Код по-прежнему проверяет и служба А (одноразовый, срок, общий с паролем счётчик неудач) — сервер только подсказывает адрес.
- Сервер не хранит семьи и ключи сопряжения; «код → ID» живёт только 5 минут в памяти.

### Совместимость

- Решение владельца 2026-10-12: старые клиенты не поддерживаются — добавление только по коду, без ввода ID.
- Без нового сервера поиск по коду не работает: клиент сообщает «Нет связи с сервером FuntiDesk» (без скрытых обходов).
- Поля и сообщения от 1000, старые стороны их игнорируют.

### Дефект сопряжения (2026-10-11)

При переделке добавления — журнал сопряжения на обеих сторонах (что пришло, что сохранено) и проверка записи в список семьи на стороне, вводящей код, до ответа «добавлен». Проверить на ноутбуке владельца, где дефект воспроизводился.

## Решения владельца (2026-10-11)

1. Окно подтверждения «Добавить в семью …?» на компьютере, показывающем код, — **да**.
2. Срок кода — **5 минут**.
3. Изменение сервера (`hbbs`) и развёртывание на `desk.funti.cc` — **после проверки на двух компьютерах**.
