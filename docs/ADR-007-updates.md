# ADR-007: Обновление кнопкой и удалённое обновление

**Статус:** принято владельцем 2026-10-11 (модель доверия к обновлениям). Реализация: этап 1 — кнопка для копии, установленной `install.ps1` (2026-10-11); установленный режим (служба) и удалённое обновление — следующие этапы.
**Дата:** 2026-10-11.
**Связано:** `docs/ROADMAP.md` (M4, «Обновление кнопкой»), `install.ps1`, `docs/SECURITY.md`, нумерация сборок `1.4.9-ft.N` (`client/build.rs`, `FUNTI_BUILD`).

## Проблема

Обновить FuntiDesk сейчас можно только командой `install.ps1`. Владелец хочет кнопку «Обновить» в клиенте и обновление компьютера члена семьи из сеанса, без подтверждения на той стороне (решение 2026-10-09).

Обновление ставит скачанную программу с правами FuntiDesk, а в установленном режиме — с правами службы. Поэтому нужно решить, чему клиент доверяет при скачивании.

## Чего опасаемся

Если чужая программа уже запущена на компьютере, обновление ничего не меняет: компьютер и так скомпрометирован. Здесь риск в другом. Все компьютеры семьи сами берут обновления из одного места — релизов `michailr1/FuntiDesk` на GitHub — и ставят их без вопросов. Подмена файла в этом месте разносится по всем компьютерам автоматически.

Пути подмены по убыванию вероятности:

1. **Захват аккаунта GitHub владельца** (пароль, токен, сессия) — злоумышленник публикует свой релиз.
2. Взлом сборки в CI (зависимость, action) — маловероятно, actions закреплены по хешу коммита.
3. Подмена по дороге — HTTPS к `github.com` её практически исключает.

Подпись релизов защищает от пути 1, только если ключ подписи хранится **вне GitHub**. Ключ в секретах GitHub Actions от захвата аккаунта не помогает: захвативший запустит CI, и тот подпишет его файл.

## Решение владельца (2026-10-11)

**Пока без подписи релизов.** Доверие к обновлению то же, что у `install.ps1`:

- источник — только `https://github.com/michailr1/FuntiDesk/releases/latest/download/…`, адрес зашит в клиент, никаких зеркал и запасных адресов;
- только HTTPS с проверкой сертификата;
- проверка SHA256 по `SHA256SUMS.txt` того же релиза (защищает от битой загрузки, не от подмены);
- аккаунт GitHub владельца защищён двухфакторным входом.

**Принятый риск:** захват аккаунта GitHub владельца означает подмену обновления на всех компьютерах семьи, которые обновятся после этого.

**Путь усиления (когда понадобится):** подпись релизов ключом, который хранится только у владельца (не в GitHub), и открытый ключ, зашитый в клиент. Клиент ставит только подписанное, при несовпадении — отказ (fail closed). Формат релиза ниже оставляет для этого место.

## Как работает обновление

### Версия релиза

- В каждый Windows-релиз CI кладёт `funtidesk-version.txt` с версией `1.4.9-ft.N` и вносит его в `SHA256SUMS.txt`.
- Клиент сравнивает только `N` (`FUNTI_BUILD`). Обновление предлагается, если `N` релиза больше своего. Сборка с `N = 0` (номер неизвестен, например локальная из shallow-клона) обновление не предлагает сама, только по явной кнопке.
- Откат на меньший `N` клиент не делает.

### «Обновить» на своём компьютере

1. «О программе»: «Проверить обновления» → «Доступна версия 1.4.9-ft.N» → «Обновить».
2. Клиент скачивает `funtidesk-version.txt`, `SHA256SUMS.txt`, `FuntiDesk-windows-x64.zip`, сверяет SHA256. Любая ошибка — сообщение и отказ, установленная версия не трогается.
3. Замена файлов и перезапуск с тем же профилем — та же последовательность, что в `install.ps1` (остановить процессы FuntiDesk, распаковать, запустить). В установленном режиме замену выполняет служба.

### Удалённое обновление из сеанса

1. При подключении клиент получает версию той стороны (своё поле протокола, номер от 1000; старая сторона его не присылает — считается «неизвестна, обновление не предлагается»).
2. Если она старше последнего релиза — в окне сеанса «На той стороне старая версия FuntiDesk» и кнопка «Обновить».
3. Кнопка доступна только в сеансе управления (у помощника и так есть полный доступ к компьютеру). Помощник передаёт только команду «обновись»; **что и откуда скачать, решает сама та сторона** по правилам выше. Адрес, файл или хеш от помощника не принимаются.
4. На той стороне — без подтверждения (решение владельца 2026-10-09), но видимое окно без кнопок «FuntiDesk обновляется, сейчас переподключимся». Скрытых действий нет.
5. Сеанс переподключается к обновлённой стороне.

## Последствия

- Обновление не добавляет нового входящего канала: команда идёт только внутри уже авторизованного сеанса управления.
- Проверка «есть ли новая версия» — один HTTPS-запрос к GitHub; без интернета или при ошибке ничего не происходит.
- Android обновляется отдельно (магазин или APK), этот ADR — только Windows.

## Реализация, этап 1 (2026-10-11)

Код — `client/src/funti_update.rs`, кнопка — «О программе» (`desktop_setting_page.dart`, `_FuntiUpdate`), CI — `ui-windows-artifact.yml` (`funtidesk-version.txt`).

- Обновляется только копия в `%LOCALAPPDATA%\Programs\FuntiDesk` (туда ставит `install.ps1`). Служба (установленный режим) и другие копии (папка сборки, `FuntiDesk-portable.exe`) получают объяснение и кнопку не видят — fail closed до следующего этапа.
- Загрузка: адрес релиза зашит; только HTTPS (rustls, проверка сертификата), без прокси; перенаправления — только на `github.com` и `*.githubusercontent.com`. `funtidesk-version.txt` и архив сверяются с `SHA256SUMS.txt`; `N` релиза должен быть больше своего (или свой `0`).
- Замена: архив распаковывается в `Programs\FuntiDesk.update\files` (пути внутри архива проверяются), оттуда запускается **новый** `FuntiDesk.exe --funti-finish-update <pid> <папка>`, старый закрывает свои процессы и выходит. Новый проверяет, что папка — именно `Programs\FuntiDesk`, а сам он запущен из `FuntiDesk.update\files`, ждёт выхода старого, переименовывает папку в `FuntiDesk.old`, копирует новые файлы, запускает установленный FuntiDesk. Ошибка копирования — папка возвращается из `.old`, запускается прежняя версия. Остатки (`.old`, `.update`) удаляются при следующем обычном запуске. Профиль (`%APPDATA%`) не трогается.
- Аргумент `--funti-finish-update <pid> <папка>` вызывает старая версия у новой, поэтому все следующие версии обязаны его принимать.

## Оповещение о новой версии (2026-10-12)

Решение владельца: о новой версии сообщает ненавязчивое окошко на главном экране, по нажатию оно раскрывается и показывает, что нового.

- Проверка — та же `check()`, при запуске (через 5 секунд) и раз в 6 часов. Ошибка проверки ничего не показывает: обновление не обязательно, а окно ошибки без действия пользователя только пугает.
- «Что нового» — файл релиза `funtidesk-whats-new.txt`: CI берёт верхний раздел `docs/WHATS_NEW.md`. Клиент скачивает его тем же `http()` (только HTTPS, редиректы только внутри GitHub), сверяет с `SHA256SUMS.txt` и ограничивает размером 16 КБ; текст показывается как есть, без разметки и ссылок. Нет файла или не сошлась сумма — окошко показывает только версию.
- «Позже» запоминает версию (`funti-update-dismissed`, локальная настройка): окошко вернётся только для следующей версии. Устанавливается обновление только по «Обновить», тем же `start()`.
- Для копий, которые кнопкой не обновляются (служба, другая папка), окошко показывает версию и причину, без кнопки «Обновить».

Код: `client/flutter/lib/desktop/widgets/funti_update_notice.dart`, `funti_update.rs` (`whats_new`), `flutter_ffi.rs` (`main_funti_whats_new`), `.github/workflows/ui-windows-artifact.yml`.

### Дефект: «папка занята» (2026-10-12)

На релизе `1.5.0-ft.12820` обновление кнопкой откатилось: `finish()` 20 секунд не мог переименовать папку установки («is busy»). Причина: старая копия запускала новую со своей рабочей папкой, а у FuntiDesk, запущенного ярлыком из «Пуска», это папка установки; рабочая папка процесса внутри неё не даёт Windows её переименовать. Утром 2026-10-11 кнопка сработала, потому что FuntiDesk был запущен не ярлыком. Исправление: `finish()` первым делом переходит в папку `.update`, `start()` запускает новую копию сразу с ней. Исправление в новой копии, поэтому обновление с уже выпущенных версий тоже проходит. Проверено на minipc: запуск с рабочей папкой внутри папки установки — `1.5.0-ft.12819` → `1.5.0-ft.12822` за 21 с.

## Любая копия (2026-10-12)

Решение владельца («надо чинить»): кнопка обновляет любую копию на её месте, а не только копию `install.ps1`.

- **Папка** (копия `install.ps1` или распакованный архив в любом месте): как раньше — `.update` и `.old` рядом с папкой, подмена папки целиком. Условие — рядом с папкой можно писать (проверяется созданием пробной папки); иначе сообщение, куда перенести FuntiDesk. `finish()` принимает папку из аргумента, но только если в ней `FuntiDesk.exe` и сам он запущен из `<папка>.update\files`. `cleanup()` удаляет только то, что оставило обновление: `.old` с `FuntiDesk.exe` и `.update` с `files`.
- **`FuntiDesk-portable.exe`**: распаковщик (`libs/portable`) передаёт программе свой путь в `FUNTIDESK_PORTABLE_EXE`. Обновление скачивает `FuntiDesk-portable.exe` релиза, сверяет с `SHA256SUMS.txt`, кладёт на место старого (старый — `.exe.old` до следующего запуска) и запускает новый с `--funti-wait-pid <pid>`: новый распаковщик ждёт выхода старой копии (до 30 с) и только потом распаковывает. Распакованную папку `%LOCALAPPDATA%\FuntiDesk\portable` как папку не обновляем: следующий запуск старого `.exe` вернул бы старую версию.
- Старые `FuntiDesk-portable.exe` (без `FUNTIDESK_PORTABLE_EXE`) кнопкой не обновляются — сообщение «один раз скачайте новый». Служба (установленный режим) — по-прежнему этапы 2–3.

Проверено на minipc: папка `Documents\FDtest` обновлена `finish()` (update installed). Полная проверка папки и portable — на двух релизах подряд.

Проверено 2026-10-13 на minipc через окно программы, `1.5.0-ft.12830` → `1.5.0-ft.12837`: копия в `Documents\FD-r1-test\folder-copy` (окошко → «Обновить» → перезапуск из той же папки, `.old` удалена); `FuntiDesk-portable.exe` (файл заменён, сумма совпала с `SHA256SUMS.txt`, перезапуск новой версией, `.exe.old` удалён). Найдено: `.update` оставалась, потому что новая копия наследовала рабочую папку программы доустановки; `launch()` теперь запускает копию с её собственной папкой.

## Этап 2: установленная служба (2026-10-14)

Решение владельца: обновление кнопкой работает и в установленном режиме (служба, `Program Files`); без него нельзя предлагать установку службы окном «Полное управление».

- Окно (пользователь) не может писать в `Program Files`, поэтому «Обновить» в установленном режиме — запрос службе по IPC (`FuntiUpdateService`). Его выполняет процесс `--server`, который в установленном режиме работает от SYSTEM.
- Служба скачивает релиз тем же `http()` (только HTTPS, редиректы только внутри GitHub), сверяет `funtidesk-version.txt` и `FuntiDesk-windows-x64.zip` с `SHA256SUMS.txt`, проверяет, что версия новее, и распаковывает архив в `<папка установки>.update\files` — рядом с установкой в `Program Files`, куда обычный пользователь писать не может, так что файлы нельзя подменить до запуска. Папка, оказавшаяся ссылкой (symlink/junction), не удаляется и не используется.
- Затем служба запускает новый `FuntiDesk.exe --update` из этой папки с правами SYSTEM в текущем сеансе (`launch_privileged_process`, как upstream-обновление). `--update` (upstream `update_me`) останавливает службу и окна, копирует файлы поверх установленных (`XCOPY`), обновляет версию в реестре и снова запускает службу и значок в трее. Окно само не закрывается — его закрывает `--update`.
- Одновременно идёт одно обновление. Любая ошибка до запуска `--update` оставляет установку нетронутой и удаляет папку `.update`; остаток после успешного обновления служба удаляет через минуту после следующего запуска (`cleanup_service`).
- Запросить обновление может любой процесс пользователя, но служба ставит только последний релиз FuntiDesk, проверенный по SHA256, и только более новый, чем установленный: подсунуть свои файлы или откатить версию так нельзя.
- Удалённое обновление из сеанса — этап 3 ниже.

Код: `funti_update.rs` (`start_service`, `request_service_update`, `cleanup_service`), `ipc.rs` (`FuntiUpdateService`), `flutter_ffi.rs`, `core_main.rs` (`--server`: очистка).

## Этап 3: обновление другого компьютера из сеанса (2026-10-17)

Решение владельца 2026-10-09: без подтверждения на той стороне — помощник в сеансе управления и так может установить что угодно; на той стороне видно, что идёт обновление.

- Компьютер сообщает в сведениях сеанса (`platform_additions`) номер своей сборки `funti_build` и `funti_updatable` — может ли эта копия обновиться (те же правила, что у кнопки: папка, portable, служба).
- Управляющая сторона сравнивает его с последним релизом (та же проверка, что «Проверить обновления»). Если там старая версия — подсказка после подключения и пункт меню сеанса «Обновить FuntiDesk на том компьютере» с подтверждением.
- Запрос — `Misc.funti_update_request` (1002), ответ — `Misc.funti_update_result` (1003): `ok:<версия>` или `err:<причина>`. Принимается только в сеансе управления экраном с разрешённой клавиатурой и мышью (не в просмотре, не в передаче файлов, звонке или терминале).
- Выполняет процесс `--server`, который обслуживает сеанс: в установленном режиме — `start_service()` (этап 2), иначе те же шаги, что у кнопки (`start()`), затем копия перезапускается. Релиз скачивает и проверяет по SHA256 сам компьютер; управляющая сторона файлов не передаёт и версию не выбирает — ставится только последний релиз FuntiDesk и только более новый.
- Человек на той стороне видит в окне подключения сообщение «FuntiDesk обновляется по просьбе подключившегося…». Сеанс прерывается и переподключается обычным «Переподключиться».
- Компьютеры со сборками до этапа 3 номер не сообщают — для них пункт не показывается.

Код: `funti_update.rs` (`add_peer_info`, `start_remote`), `server/connection.rs` (подсказка в сведениях, обработка запроса), `client/io_loop.rs` (ответ), `ui_session_interface.rs`, `flutter_ffi.rs` (`session_funti_update_peer`), Flutter `common/widgets/funti_remote_update.dart`, меню сеанса `toolbar.dart`.
