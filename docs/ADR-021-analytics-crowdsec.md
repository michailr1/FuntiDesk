# ADR-021: блокировка перебора входа статистики через CrowdSec

Статус: принято в рамках самостоятельной серверной приёмки задачи #128, порученной владельцем 2026-11-11 (исключение в AGENTS.md). Номер 020 зарезервирован клиентским журналом в #129; эта работа с ним не пересекается. Реализация/приёмка — #131, дашборд — #130. Ни новых сервисов, ни новой сборки Caddy не требуется.

## Факты и решение

CrowdSec и firewall-bouncer работают; caddy-logs/http-logs/http-generic-bf установлены. Access log Caddy уже читается acquisition type=caddy; существующий 401 Basic соответствует auth_fail. Offline explain подтверждает GET/401→auth_fail, GET/200→не auth_fail. Сценарий имеет capacity=5, leakspeed=10s, blackhole=1m, remediation=true; это leaky bucket, не обещание бана строго после N ошибок.

Пробел: бouncer подключён только к INPUT; входящий опубликованный Docker-порт идёт через FORWARD/DOCKER-USER. Используется существующий бouncer, без второго acquisition, новых ключей, HTTP-плагина, контейнера или хранилища. Новая собственная цепь FUNTIDESK_HTTPS_CS подключается только к DNAT TCP destination 172.31.251.4:443 (фиксированный адрес Caddy из #127). INPUT сохраняется. Остальные forwarded-порты не направляются в CrowdSec.

**Граница блокировки — HTTPS общего Caddy, не один URL.** IP, получивший решение ban, потеряет доступ и к другим сайтам на этом опубликованном 443. Это естественная граница выбранного IP-bouncer; VPN-порты, 80, 8442 и чужие forwarded-потоки новым правилом не охватываются. Если понадобится блокировать только URL статистики, нужен HTTP-bouncer и новое архитектурное решение. Basic Auth остаётся обязательным независимо от CrowdSec.

Bouncer сам управляет своими jumps/ipsets: в его iptables_chains добавляется собственная цепочка, а не прямое внешнее обращение к удаляемой CROWDSEC_CHAIN или текущим именам sets. Принятый drop-in существующего unit идемпотентно создаёт IPv4/IPv6 цепочки и ровно один scoped IPv4 jump перед стартом bouncer. PartOf/After Docker обеспечивают повторную инициализацию при его restart; Docker в production для теста не перезапускается. Привязка к фиксированному Caddy IP требует сохранения overrides из #127. При очередном base-only пересоздании сначала восстановить правильную сеть, не расширять firewall на всю подсеть.

На проверенном desk Caddy публикует HostIp=0.0.0.0, IPv6 publication отсутствует. Новый jump касается IPv4. Исходная INPUT-защита IPv6 сохраняется; если появится IPv6 publication/forwarding, до объявления защиты нужен отдельный IPv6 packet test и ограниченное правило. IPv6 не отключается ради задачи.

## Проверки и приватность

Изолированный root-only test scripts/security/test-crowdsec-forward.py использует unshare --net: собственные таблицы, sets, veth, DNAT и два дочерних namespace. Точное правило из drop-in проверено пакетами: доступ до бана, блокировка DNAT HTTPS, сохранение другого опубликованного порта и non-DNAT, доступ после unban. Host firewall не меняется этим тестом; процессы удаляются в finally.

После установки обязательны: тот же packet test; controlled live тест с временным network namespace и benchmark-адресом (не IP владельца/DE); обнаружение неверных Basic-логинов, decision/ipset и фактическая блокировка, снятие только своего тестового решения и возврат доступа. Не создавать баны реальным посетителям ради теста. Затем проверить restart bouncer, отсутствие дублированного jump, стабильность Docker-контейнеров, соседних сайтов, VPN/SSH и неизменность остальных правил. Итог — в едином отчёте серверной приёмки.

Сырые логи, закрытый URL, Authorization, cookies, API-ключи и персональные IP не копируются в GitHub или ответы инструментов. Используется существующий локальный log с текущей ротацией; log_credentials не включается. Новая внешняя телеметрия CrowdSec не настраивается. Тестовые данные и конфигурационные backup остаются на desk в закрытом updates/.

## Поставка и откат

Порядок воспроизводимых команд — docs/ACCOUNT_DEPLOYMENT.md, раздел «CrowdSec для HTTPS статистики». Установка меняет только собственный jump/цепь, список chains существующего bouncer и отдельный drop-in. CrowdSec/Caddy/VPN не перезапускаются; перезапускается только firewall-bouncer.

Откат: удалить только помеченный FuntiDesk jump; восстановить прежний bouncer config и удалить собственный drop-in; daemon-reload, restart только bouncer; после удаления его managed jumps удалить пустые собственные цепи. Не flush INPUT/FORWARD/DOCKER-USER, не сбрасывать существующие decisions/ipsets. Проверить INPUT и доступность HTTPS. При сбое установки автоматически возвращается исходный конфиг и удаляется собственный jump; старые блокировки сохраняются.
