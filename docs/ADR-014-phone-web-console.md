# ADR-014: веб-консоль FuntiDesk для телефона

Статус: принято владельцем 2026-10-18. Дополняет ADR-010 (веб-управление) и ADR-012 (браузерное подключение).

## Контекст

Отдельного приложения для iPhone не будет без платной учётной записи разработчика Apple; владелец платить не хочет. Браузерное подключение `/connect/` уже работает в Safari на iPhone (видео, мышь, клавиатура — проверено владельцем 2026-10-18), но с телефона неудобно: нет полного экрана, непонятно, как сделать правый клик и где настройки, нет масштаба, файлов, выбора компьютера из кабинета. Макет и разбор других клиентов (Chrome Remote Desktop, Microsoft Remote Desktop, AnyDesk/RustDesk, TeamViewer, Guacamole/noVNC): https://claude.ai/artifact/4hk9NBwLcBNTNriB8ATQZM.

## Решение

Довести существующие `/connect/` и `/account/` до удобной работы с телефона. Новых сервисов, доменов и процессов на desk нет.

1. **Одна страница для телефона.** Кабинет и подключение — одна страница: после входа по почте — свои компьютеры, избранное, недавние с кнопкой «Открыть» (ID подставляется), без входа — поле ID. Страница ставится на экран «Домой» (web app manifest, `display: standalone`) и открывается без адресной строки.
2. **Сеанс.** Экран компьютера на весь экран и одна плавающая перетаскиваемая кнопка меню. Работает в вертикальной и горизонтальной ориентации; при повороте экран компьютера подстраивается, меню и строка клавиш раскладываются под ширину. Экран телефона не гаснет во время сеанса (Screen Wake Lock, отказ браузера не ошибка).
3. **Мышь.** По умолчанию — тачпад: палец двигает курсор, касание — клик, касание двумя пальцами — правый клик, двумя пальцами вверх-вниз — прокрутка, двойное касание и ведение — перетаскивание. Второй режим — касание (клик там, где палец; долгое нажатие — правый клик), переключается в меню. Подсказка жестов при первом сеансе и из меню.
4. **Масштаб.** В меню: «По размеру экрана», «1:1» и плавное увеличение; щипок увеличивает, двумя пальцами — двигать увеличенный экран. Уточнение владельца 2026-10-18: в режиме тачпада при увеличении экран автоматически следует за движением курсора, удерживая его в центре видимой области, насколько позволяют края рабочего стола. Учитываются поворот и место, занятое клавиатурой. После ручного перемещения двумя пальцами слежение возобновляется при следующем движении курсора; в режиме прямого касания автопрокрутки нет.
5. **Клавиатура.** Системная клавиатура через поле ввода (русская раскладка, диктовка), без второй панели клавиш при обычном вводе. Уточнение владельца 2026-10-18: спецклавиши открываются из меню по запросу: Esc, Tab, Ctrl, Alt, Shift, Win, стрелки, Del, F1–F12, частые сочетания. Модификаторы залипают на одно нажатие, двойное — до отмены.
6. **Меню сеанса.** Режим мыши, клавиатура, монитор, масштаб, качество, буфер обмена, файлы, Ctrl+Alt+Del, «Завершить». Действия, влияющие на компьютер (Ctrl+Alt+Del, блокировка, перезапуск), — с подтверждением.
7. **Файлы.** Отправка с телефона и скачивание с компьютера по протоколу FuntiDesk; права компьютера (ADR-006) действуют как обычно.

## Не делаем

- **Вход без пароля с телефона (телефон как член семьи) — отклонено владельцем 2026-10-18 как рискованное:** ключ в браузере может использовать тот, кто подменит страницу на desk. Первый вход требует пароль компьютера. По уточнению владельца 2026-10-18 разрешено ограниченное восстановление той же вкладки (ниже); постоянной браузерной идентичности нет.
- Звонки, камера, работа в фоне, управление самим телефоном — только в нативном приложении.
- Настоящий полноэкранный режим в Safari без «Домой»: на iPhone WebKit даёт его только видео.

## Этапы

1. Сеанс для телефона (пункты 2–6, кроме файлов и буфера обмена).
2. Одна страница с кабинетом (пункт 1) и буфер обмена в обе стороны.
3. Файлы (пункт 7).

Каждый этап — отдельные PR по правилам агентов исполнения (`AGENTS.md`), приёмка — на iPhone владельца в Safari и с экрана «Домой», плюс настольный Chrome не должен сломаться.

## Восстановление после сворачивания — уточнение владельца 2026-10-18

Владелец подтвердил восстановление без повторного ввода при возврате в ту же вкладку в течение 5 минут и автозаполнение постоянного пароля средствами Apple «Пароли»/Safari. Принято архитектором 2026-10-18 (#76, #78); уточнение для reload приведено ниже.

- Только для телефонного интерфейса: производное от пароля (SHA-256 от пароля и соли) хранится в RAM вкладки во время разрешённого сеанса, затем не более 5 минут после ухода в фон или обрыва. Это секрет, эквивалентный паролю для этой соли; в storage/URL/cookie/логи/аккаунт он не записывается. Срок проверяется перед повторным использованием и после асинхронных операций; при замороженном Safari очистка выполняется, когда JS снова получает управление, истёкший секрет не используется.
- Одна автоматическая попытка после возвращения/обрыва. Новый сеанс заново проверяет подписи ID/ключей, закреплённый ключ hbbs, свежий challenge и права компьютера. Память связана с точным ID, проверенным ключом компьютера и солью. Существующие my_id/session_id сохраняются для штатного протокола, сами по себе доступ не дают.
- «Завершить», уход/перезагрузка страницы, истечение срока, отказ входа, смена ключа/соли, некорректное сообщение или ошибка криптографии очищают секрет. Повтор после неудачной автоматической попытки требует пароль. Права ввода проверяются заново; почтовая сессия разрешением не становится.
- Автозаполнение использует стандартные username/current-password атрибуты. Сохранением и подтверждением (обычно Face ID) управляет системный менеджер по выбору пользователя, FuntiDesk своего постоянного хранилища паролей не создаёт. Для этого рекомендуется постоянный пароль; временный может измениться на компьютере и тогда восстановление будет отклонено.
- Гарантии удержания Safari в фоне нет: если iOS выгрузила вкладку, нужны новый вход или системное автозаполнение. Новых сервисов, схем хранения и изменений wire-протокола нет.

## Восстановление после обновления страницы — принято 2026-10-18

Владелец запросил сохранение сеанса после обновления страницы. Раздел о RAM выше описывает принятое поведение #76; этот раздел вводит ограниченное исключение, принятое архитектором 2026-10-18 (#76, #78). До merge в main новое хранение на desk не включается. Расширять это хранение (localStorage, IndexedDB, больший срок, другие устройства/desktop) можно только через новый ADR.

Простейший вариант без нового сервиса, серверного токена и изменений Windows — кратко сохранить уже используемое производное пароля в `sessionStorage`. RAM исчезает при reload, системный менеджер паролей требует действий пользователя; шифрование записи ключом из той же записи не скрывает секрет от кода страницы.

- Только телефонный интерфейс. В обычном сеансе данные остаются в RAM; запись создаётся синхронно при `pagehide` только для сеанса, подтверждённого первым кадром. Во время незавершённого повторного входа запись не создаётся. RAM и транспорт прежней страницы очищаются/закрываются.
- Секретная запись `funtidesk.phone-reload.v1`, JSON версии 1: ID компьютера, проверенный public key (32 байта), соль, производное SHA256(password+salt) (32 байта), прежние clientId/sessionId, createdAt/expiresAt в миллисекундах. Чистого пароля, ключей шифрования, состояния кабинета и прав в записи нет. Запись ограничена 4096 символами, поля/длины/диапазоны проверяются строго. По уточнению ревью #80 рядом при pagehide подтверждённого сеанса записывается несекретная метка времени `funtidesk.phone-reload.attempt`: она разрешает только сообщение о пропавшей записи, не вход; проверяется в пределах пяти минут и удаляется при чтении/очистке вместе с записью.
- `expiresAt` — не позже пяти минут от сохранения; уже начавшийся срок после фона/обрыва не продлевается. Будущие createdAt, истёкшие и чрезмерные сроки отклоняются. Новая страница читает и удаляет запись до первого обращения к компьютеру. Одна автоматическая попытка разрешена только при navigation type `reload`, том же origin и отсутствии другого ID в ссылке. Обычный переход, Back/Forward и desktop запись удаляют без входа.
- Повтор использует прежнюю проверку подписей, тот же ключ/соль компьютера, новый challenge и шифрование; действующие права определяет компьютер. При успешном первом кадре запись уже отсутствует, данные остаются в RAM. Только подтверждённый новый сеанс может создать следующую запись при следующем обновлении. «Завершить», отказ, повреждённая запись и недоступное хранилище оставляют обычный вход без автоматического цикла повторов.
- Производное — секрет, эквивалентный паролю для этой соли, доступный JavaScript того же origin. Пять минут проверяет клиент: это не серверный отзыв и не ограничение использования уже украденного секрета. Browser sessionStorage может сохраняться на диске или копироваться при восстановлении/дублировании вкладки; физическое стирание и строгая уникальность вкладки не обещаются. LocalStorage, cookie, URL, аккаунт и логи для секрета не используются.
- `pagehide` и сохранение sessionStorage не гарантированы при аварийной выгрузке iOS. В таком случае, после истечения срока или смены временного пароля нужен обычный вход/системное автозаполнение. Без принятых изменений Windows нельзя гарантировать восстановление с уже сменившимся временным паролем.

Приёмка: настоящий reload после разрешённого сеанса, свежий proof и прежние client/session ID; новое view-only; End; истечение срока без исполнения таймера; недопустимые даты/формат; смена соли/ключа/пароля; reload до первого кадра; другой ID и обычная навигация; запрещённый sessionStorage. Физический iPhone проверяется после принятия и выкладки. API, БД, Caddy и wire-протокол не меняются.
