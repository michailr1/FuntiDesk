# ADR-015: декодирование файлов в браузере

Статус: решение реализации #67, применяется после принятия PR плана. Владелец поручил передачу файлов 2026-10-19; реализация и проверка выполняются в существующем проекте, без нового сервиса. Дополняет пункт 7 ADR-014.

Компьютер FuntiDesk передаёт файлы по существующему протоколу, сжимая блоки до 128 KiB через Zstandard. В Safari нет гарантированного нативного декодера; прежние JS-зависимости не поддерживают Zstandard. Передавать файл через сервер кабинета, менять wire/Windows ради отказа от сжатия или писать собственный декодер сложнее и рискованнее.

Используем ровно одну зависимость `fzstd@0.1.1` (MIT), закреплённую npm lock/integrity. Код включён в прежний session.js и third-party notices, без CDN/нового endpoint/процесса/WASM. Перед декодированием проверяются один frame, отсутствие dictionary/skippable frames, объявленный размер/окно ≤128 KiB и ограниченные размеры/число блоков; фиксированный выходной буфер. Суммарно один файл до 50 MiB, без бесконтрольной распаковки и долговременного хранения.

Файловый канал отдельно проходит прежние подписи, ключ компьютера и парольный challenge; он не авторизуется почтовой сессией. На первом открытии используется пароль с системным автозаполнением, сразу очищаемый; не расширяем принятое хранение recovery-секрета на desktop/файлы. Права и запреты проверяет компьютер. Новый протокол и изменения нативного клиента не вводятся.

Прогресс/отмена и Blob живут только в RAM открытой панели. iPhone получает готовый файл по явному нажатию «Сохранить»; сохранением управляет Safari/ОС. При закрытии освобождаются соединение, буферы и Blob URL. Обещания фоновой передачи, докачки или больших файлов нет. Лицензия декодера включается в notices при сборке; обновление версии требует отдельного изменения lock/проверок ограничений.
