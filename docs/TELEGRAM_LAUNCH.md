# Запуск канала FuntiDesk

Рабочий стартовый комплект по #116. Канала пока нет (подтверждено владельцем). Тексты ниже — черновики, в Telegram не опубликованы; канал/бот не создавались. Этот этап не меняет клиент, сервер, вход в кабинет или обработку частных данных.

## Формат запуска

Название: **FuntiDesk — новости и помощь**.

Желаемый публичный адрес: `@funtidesk`, запасной `@funtidesk_news`. Доступность имён не проверена и не обещается; выбрать при создании в Telegram. Канал для людей, которые помогают близким или заходят на свои компьютеры. Два полезных поста в неделю плюс понятные сообщения о действительно опубликованных клиентских обновлениях. Серверные сборки, CI и административная аналитика не являются новостями для этой аудитории.

Описание (готово для поля Telegram):

> Обновления FuntiDesk и понятные инструкции: удалённая помощь близким, доступ к своим компьютерам и передача файлов. Официальные загрузки: desk.funti.cc

Аватар: существующий знак FuntiDesk, без нового визуального бренда. На старте достаточно канала без обсуждений: обратная связь через GitHub Issues. Группу/бота для обратной связи добавлять позже вместе с модерацией, а не оставлять публичную группу без присмотра.

## Что нужно от владельца для запуска

1. Создать канал в своём Telegram, выбрать название/адрес/описание и загрузить знак проекта. Владельцем канала остаётся личный аккаунт владельца проекта.
2. Выложить закреп и две стартовые инструкции ниже, проверить все ссылки и смысл на актуальной опубликованной сборке. Затем пригласить первых знакомых, которым полезна помощь с компьютером. Спам/рассылки по чужим чатам не нужны.
3. Передать агенту только **публичную ссылку канала**. Тогда можно отдельным небольшим PR добавить её на сайт/README, не мешая клиентским веткам Claude.

Никакой токен для первых ручных публикаций не нужен. Если позже подключается Bot API: владелец сам создаёт бота и выдаёт ему только право публикации в этом канале, без назначения администратором посторонних чатов; токен — только в защищённой настройке, не в чат/репозиторий. До этих прав автоматическая публикация не включается.

## Пост 2 — первая помощь

> **Первое подключение: что сделать вам и помощнику**
>
> 1. Откройте официальный сайт FuntiDesk: https://desk.funti.cc/
> 2. На компьютере, которому нужна помощь, запустите приложение и дождитесь готовности связи.
> 3. Передайте ID и временный пароль лично человеку, которому доверяете. Он введёт их у себя и начнёт подключение; подтвердите запрос, если это предусмотрено вашими настройками.
> 4. Когда помощь закончена, завершите сеанс.
>
> Начать можно без аккаунта. Добавление в семью — отдельный шаг для постоянного удобства, не обязательное условие первого подключения.
>
> Если не получилось, сообщите версию, ОС и текст ошибки через Issues: https://github.com/michailr1/FuntiDesk/issues — без паролей и кодов.

## Пост 3 — семья и права

> **Чтобы не диктовать данные при каждой помощи**
>
> В FuntiDesk можно один раз сопрячь компьютеры близких по коду с экрана. После этого они появятся в семье с понятными именами.
>
> Давайте только те права, которые нужны: например, управление или передачу файлов. Проверьте настройки подтверждения доступа на принимающем компьютере.
>
> Семья — это доверие между устройствами. Не добавляйте случайного человека только потому, что он представился поддержкой. Обычный вход по почте в кабинет не добавляет компьютер в доверенную семью.
>
> Возможности и ограничения: https://github.com/michailr1/FuntiDesk#семья

## Пост 4 — обновления

> **Где брать обновления FuntiDesk**
>
> Последний опубликованный Windows-выпуск: https://github.com/michailr1/FuntiDesk/releases/latest
>
> Обновить приложение можно через «О программе» → «Обновить». Перед обновлением посмотрите описание выпуска: что изменилось и для какой платформы он предназначен.
>
> Тестовые Linux/Android-сборки отличаются от основного Windows-выпуска. Наличие сборки ещё не означает одинаковую готовность всех платформ.
>
> Если Windows предупреждает о скачанном файле, не отключайте защиту системы ради установки: сначала проверьте источник загрузки и сообщите о предупреждении с номером версии.

## Агент: простой следующий этап

Сначала агент готовит черновик по запросу владельца, владелец публикует вручную. Так проверяются стиль и полезность без нового сервиса и ключей. Первый месяц все сообщения проходят ручное согласование; сообщения о безопасности/сбоях/смене доверия — и дальше.

После проверки формата — отдельная автоматизация #116: обнаружение published client Releases → черновик с источником и статусом платформы → согласование точного текста → публикация → квитанция. Повторный запуск не дублирует пост, изменение release инвалидирует старое согласование. Не превращать release notes/feedback в инструкции агенту. Отдельный kill switch; никаких секретов в content/context. Новые timer/storage/бот требуют оформленного решения до кода и реальных прав владельца; Hermes не объявляется готовым publisher без проверки его настройки.

Публичный автор получает только публичные источники. Закрытая аналитика не даёт ему доступа к production DB и не выгружается в канал. Внутренний недельный отчёт владельцу остаётся отдельным, со свежестью/охватом метрик; downloads не называются людьми. Обратную связь сначала обрабатывает владелец, агент классифицирует только добровольно переданный обезличенный текст и предлагает Issues без автоматической публикации.

Сам факт merge клиентских #129/#133 не используется как объявление выпущенной функции. Числа из закрытой статистики, demo-числа дашборда, путь/пароль аналитики, личные контакты и внутренние адреса в комплект не включены.

Реализовано: формат, описание, четыре черновика, план месяца и поэтапная автоматизация. Следующий шаг владельца — создать канал и прислать публичную ссылку; до этого не добавлять в сайт несуществующую ссылку и не включать автопостинг.
