# Главная сайта и оформление выпусков (#82)

Подготовлено из main `ebae9e4cd`, включая Android fix #81. Владелец 2026-10-19 разрешил Codex самостоятельно проверить, влить и выложить #83 без ожидания отдельного ревью. Поставка главной подготовлена отдельно от API.

## Поведение

- Главная больше не загружает симулятор, не показывает вымышленные устройства и не имитирует подключение. Вместо него — загрузки Windows EXE/ZIP и конкретного тестового Android APK с SHA-256 и ссылками на выпуски по ОС.
- Веб-консоль `/connect/` видна в шапке, первом экране и разделе платформ. Кабинет `/account/` обозначен иконкой профиля с доступным именем и отдельной карточкой. Вход в кабинет не предоставляет доступ к компьютеру.
- Светлая, тёмная и системная темы сохранены. Для iOS/macOS/Linux не обещаются неопубликованные приложения.
- В 48 опубликованных GitHub Releases унифицированы только названия: 25 Windows, 15 тестовых Android, 7 серверных и 1 служебный журнал. Старые названия и метаданные сохранены приватно для обратного переименования. Существующие workflow меняют только будущие title, без новых запусков/публикаций.

## Проверка

Chromium: ширины 320/390/768/1440, все три темы, сохранение темы после reload, доступные имена ссылок, якоря, отсутствие горизонтальной прокрутки и ошибок JS. Главная загружает только HTML, CSS, переключатель темы и эмблему; скрипты симулятора, API и WebSocket не вызываются. Ссылки дистрибутивов сверены с ID/именами опубликованных assets; это не повторная проверка бинарных файлов.

Manifest/воспроизводимая упаковка 25 файлов, JS syntax, YAML и изменение только title в workflow, product identity guard, diff --check — прошли. После переименования Releases сверены прежние release ID, теги, target commit, body, draft/prerelease, published_at и наборы/ID/размеры/URL/digest файлов. Windows latest остаётся `funtidesk-windows-242213dd906b`.

## Поставка и ограничения

Только принятый main по существующему порядку статической поставки; Caddyfile, DNS, серверный API, данные и клиентские права эта работа не меняет. Для этой задачи существующий helper получил `--landing-only`: четыре файла главной проверяются по manifest и заменяются в копии действующего webroot. Все остальные файлы, включая кабинет, консоль и их SOURCE_COMMIT, остаются прежними; отдельная квитанция отмечает источник главной. Семь тестов helper проверили также сохранение кабинета/консоли на v4, откат и отказ при symlink. Полная поставка UI #72 по-прежнему требует API v5 из #71; блокировка #58 этой работой не снимается. Откат страницы — предыдущий webroot; названий Releases — сохранённые title. Не менять теги/файлы/latest ради оформления.

Настоящий iPhone не проверен. Android имеет отладочную подпись и остаётся тестовым; его URL закреплён, обновлять ссылки следует при принятии следующего APK. Исторические скрипты демо остаются в дереве исходников и архиве, но главная на них не ссылается и не исполняет. GitHub показывает общую ленту Releases; ссылки по ОС используют штатный фильтр, отдельные репозитории не создаются.
