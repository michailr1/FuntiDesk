# Главная сайта и оформление выпусков (#82)

Владелец разрешил самостоятельную проверку/merge/поставку без ожидания отдельного ревью. После жалобы на #83 сайт откатан на прежний webroot `6277d1b4431a`; кабинет, консоль и API не менялись.

## Исправление после первой выкладки

Первая версия ошибочно заменила исходный дизайн и анимированные буквы. Проверка только в чистом браузере также пропустила смешивание нового HTML с прежним `/style.css` из кэша. Проблема воспроизведена в Chromium с прогретым кэшем: SVG разросся до 1296 px, ссылка «К содержимому» стала видимой, CSS темы отсутствовал. Прежний отчёт о чистом браузере не подтверждал поведение в существующей вкладке владельца.

Теперь за основу взята исходная главная из `ebae9e4cd`: сохранены буквы, их сборка/распад в сеть, движение при наведении, управление анимацией, палитра и композиция. Удалён только симулятор сеанса и его скрипты. `app.js` содержит исключительно геро-анимацию. Нет вымышленных подключений/ввода паролей/звонков/передач; иллюстративные устройства и схема семьи остаются частью исходного оформления.

Добавлены прямые Windows EXE/ZIP/SHA-256, тестовый Android APK/SHA-256, явные переходы в настоящую веб-консоль и иконка кабинета 24×24. FAQ описывает настоящие возможности. CSS/JS получают content-version в URL, проверяемый по SHA-256, чтобы старый кэш не применялся к новой странице. В системной теме берётся `event.matches`: сохранённый MediaQueryList может ещё возвращать прежнее значение в момент события; светлая/тёмная темы и цвет букв обновляются согласованно.

## Проверка

`npm --prefix web-client run test:landing`: настоящий HTTP-кэш предварительно заполнен старыми unversioned CSS/JS, затем открывается новая главная. На 320/390/768/1440 проверены видимые цвета светлой/тёмной/системной тем, смена системной темы, сохранение выбора при reload, непустой canvas и превращение букв в сеть, пауза/возобновление, размер SVG, отсутствие симулятора/лишней надписи/overflow/ошибок JS и корректные якоря. Проверка добавлена в существующий Browser client CI без новых зависимостей.

Семь тестов статической поставки проверяют сохранение кабинета/консоли на v4, откат и отказ при symlink. Manifest 25 файлов, JS syntax, YAML, product identity guard и diff --check проходят. Настоящий iPhone не проверен. CI в очереди не считается пройденным.

## Поставка и релизы

Существующий `--landing-only` переносит пять файлов (index.html, style.css, theme.js, mark.svg, app.js) по manifest в копию действующего webroot. Кабинет/консоль и их SOURCE_COMMIT сохраняются побайтово; источник главной записывается в закрытую квитанцию. API и DB остаются v4, #58 отдельно. Откат — прежний webroot и штатное пересоздание только Caddy, без изменения его image/config/сетей и соседних контейнеров.

В 48 существующих Releases ранее изменены только названия: 25 Windows, 15 тестовых Android, 7 серверных и 1 служебный журнал. Теги, исходники, описания, файлы и Windows latest сохранены. Эти изменения оформления выпусков не отменяются исправлением главной. Android имеет отладочную подпись и остаётся тестовым; его URL закреплён. Полная поставка UI #72 по-прежнему требует сначала API v5.
