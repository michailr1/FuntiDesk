## Важное ограничение среды

Сессия Claude работает в песочнице: её записи в `%APPDATA%` попадают в виртуальную копию каталога и не видны процессам вне песочницы (проверено задачей планировщика от SYSTEM: `C:\funtidesk-accept` и `Program Files` видны, созданные сессией `%APPDATA%\FuntiDesk` и `%APPDATA%\RustDesk` — нет). Но установка службы читает профиль пользователя от имени SYSTEM, вне песочницы, — см. «Служба».

### Служба

`--silent-install` при установке запускает импорт конфигурации пользователя от имени SYSTEM. Журнал импорта: `Empty source config, skipped`, служба сгенерировала новый ID `114350950`. Воспроизведено задачей планировщика от SYSTEM; от имени пользователя тот же файл читается нормально. Причина — песочница сессии: профиль, созданный сессией, процессу SYSTEM не виден (`dir` от SYSTEM: «файл не найден»). Код импорта (`core_main.rs::import_config`, `confy::load_path`) PR #12 не менял по смыслу: при отсутствии файла upstream так же молча возвращает пустой конфиг.

Перепроверка вне песочницы: профиль владельца возвращён в `%APPDATA%` процессом вне дерева Claude (задача планировщика от имени пользователя), служба переустановлена так же. Импорт увидел профиль, но ID сначала остался `114350950`: upstream `import_config` перезаписывает конфиг службы, только если файл пользователя новее, а `--uninstall` не удаляет профиль службы (`C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\FuntiDesk`), оставшийся от первой установки. После переноса этого остатка и повторной установки служба получила ID `1627400601`.

Вывод: не дефект PR #12. Замечание на будущее (upstream-поведение): после удаления и повторной установки служба сохраняет старый ID службы, а не ID портативной копии. Оценить отдельно вместе с политикой удаления (Phase 2 в `FUNTIDESK_IDENTITY_NAMESPACE.md`).

Прочее: `--uninstall` завершается с кодом 1, хотя служба, `Program Files\FuntiDesk` и запись удаления убраны.
