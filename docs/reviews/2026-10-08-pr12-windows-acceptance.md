### Служба

`--silent-install` при установке запускает импорт конфигурации пользователя от имени SYSTEM. Журнал импорта: `Empty source config, skipped`, служба сгенерировала новый ID `114350950`. Воспроизведено задачей планировщика от SYSTEM; от имени пользователя тот же файл читается нормально. Причина — песочница сессии: профиль, созданный сессией, процессу SYSTEM не виден (`dir` от SYSTEM: «файл не найден»). Код импорта (`core_main.rs::import_config`, `confy::load_path`) PR #12 не менял по смыслу: при отсутствии файла upstream так же молча возвращает пустой конфиг.

Перепроверка вне песочницы: профиль владельца возвращён в `%APPDATA%` процессом вне дерева Claude (задача планировщика от имени пользователя), служба переустановлена так же. Импорт увидел профиль, но ID сначала остался `114350950`: upstream `import_config` перезаписывает конфиг службы, только если файл пользователя новее, а `--uninstall` не удаляет профиль службы (`C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\FuntiDesk`), оставшийся от первой установки. После переноса этого остатка и повторной установки служба получила ID `1627400601`.

Вывод: не дефект PR #12. Замечание на будущее (upstream-поведение): после удаления и повторной установки служба сохраняет старый ID службы, а не ID портативной копии. Оценить отдельно вместе с политикой удаления (Phase 2 в `FUNTIDESK_IDENTITY_NAMESPACE.md`).

**Находка для продукта (upstream-поведение, не дефект PR #12):** `import_config` переносит конфиг пользователя в службу, только если файл конфига старше `FuntiDesk.exe` (`get_modified_time(path) < get_exe_time()`). Перед последней установкой профиль был изменён в 08:04, а exe собран в 07:28 — установка сгенерировала бы новый ID. Для проверки runtime скопирован в новый каталог, у `FuntiDesk.exe` выставлено текущее время изменения (как у только что скачанного файла, SHA256 тот же) — служба получила ID `1627400601`. Риск: пользователь, который долго пользовался портативной копией и потом нажал «Установить», может получить новый ID. Учесть в задаче «Полный доступ без сюрпризов» (ROADMAP M4).

Прочее: `--uninstall` завершается с кодом 1, хотя служба, `Program Files\FuntiDesk` и запись удаления убраны.

Диагностика: `tcpdump` на `desk.funti.cc` показал, что `hbbs` трижды отправляет ноутбуку запрос (UDP 38 байт) на адрес его регистрации `109.173.98.95:56502`, но ноутбук не реагирует, и в журнале клиента ноутбука запроса нет; собственные регистрации ноутбука (раз в ~16 с) и ответы на них проходят. Вывод: на сетевом пути ноутбука UDP-сопоставление живёт меньше интервала регистрации, входящие запросы приходят в уже закрытое сопоставление. Дополнительно в журнале `hbbs` адрес регистрации ноутбука периодически переключается между `109.173.98.95` и `173.249.195.36` (VPN-узел на том же сервере). Режим «Отключить UDP» с OSS-сервером не работает. Это задача MIK-16 (NAT refresh): чаще обновлять регистрацию на таких сетях или держать сигнальный канал по TCP. Камера не проверена.
