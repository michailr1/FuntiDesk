# Проверка ответа кабинета при расхождении часов Windows

После восстановления API на Core пользователь сообщил ошибку «Не удалось проверить ответ кабинета». На снимке список уже обновлён, но последнее общение устройства осталось старым. Чтение Core подтвердило: запросы nonce для bind/family/sync создаются, подписанные операции не завершаются; у family/sync идентификатор аккаунта, Funti ID и публичный ключ совпадают с устройством. Часы Core синхронизированы NTP. Причина именно на физическом клиенте пока требует проверки после синхронизации его часов.

В клиентской проверке воспроизведён дефект: сервер выдаёт nonce на 300 секунд, а клиент допускает `expires_at <= local_now + 300`. Поэтому даже отставание Windows на одну секунду приводит к отклонению корректного ответа до подписи. Регрессионная проверка с server time 1000 и client time 999 падает до исправления.

Исправление допускает до 300 секунд отставания локальных часов: верхняя граница равна `local_now + 600`. Локальная проверка уже истёкшего nonce, точное совпадение аккаунта/устройства/ключа/действия/hash и формат подписываемого сообщения сохранены. Сервер не меняется: срок 300 секунд, проверка подписи и одноразовое потребление остаются обязательными. Новых состояний, сервисов и зависимостей нет.

Поверхность изменения: только `Nonce::message` в клиентском account-протоколе, используемом Windows service для bind/family/sync/ack. Остальные пути клиента, API, SQLite, SMTP, Caddy и hbbs/hbbr не меняются. В существующем тесте сообщения клиента и сервера сверяются для всех четырёх действий при небольшом расхождении часов; тест отклонения слишком далёкой даты обновлён под новую границу.

Локально прошли Rust tests и Clippy `-D warnings`. Windows-сборка и результат на двух физических компьютерах будут записаны после проверки. До этого ошибка на устройстве не объявляется устранённой; M3 остаётся открытым.
