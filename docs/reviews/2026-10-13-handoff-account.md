# Передача: личный кабинет FuntiDesk (2026-10-13)

Кому: Codex (исполнитель работ по личному кабинету, ЛК). От: Claude (ведущий архитектор/разработчик, `AGENTS.md`).
Решение владельца 2026-10-13: вся работа по ЛК — у Codex, параллельно с остальной работой Claude; Codex работает с агентом Hermes, который ведёт сайт `desk.funti.cc`.

Этот документ — точка входа. Источник истины — репозиторий: `AGENTS.md`, ADR, `docs/ROADMAP.md`, PR. Если документ и код расходятся — прав код, документ поправить.

## 1. Что строим и что уже решено

Прочитать до кода, целиком:

- **`docs/ADR-009-account.md`** (принят 2026-10-13) — ЛК: назначение, вход, что хранит сервер, безопасность, этапы.
- **`docs/ADR-006-family-access.md`**, особенно раздел «Права членов семьи» — семья и права, с которыми ЛК работает.
- **`docs/ADR-008-family-pairing-by-code.md`** — как устроено сопряжение по коду через сервер (образец своих сообщений, подписи ключом устройства, лимитов).
- `docs/SECURITY.md`, `docs/NETWORK_ALLOWLIST.md`, `docs/SERVER_DEPLOYMENT.md`, `docs/FUNTIDESK_PATCHES.md`, `docs/UPSTREAM.md`.

Решения владельца, которые не обсуждаются заново:

1. ЛК нужен; свой сервис, **без** закрытой серверной части RustDesk Server Pro и без upstream-аккаунтов.
2. **Этап 1:** (а) вход на новом компьютере → сразу видны свои устройства и семья; (д) удалённо убрать устройство из семьи (потеряно, продано).
3. **Вход — по почте с кодом**, письма отправляет **наш сервер** (`desk.funti.cc`, свой SMTP). Без Telegram, без Google/Яндекс, без паролей, без почтовых сервисов. Почта — и вход, и восстановление.
4. **Страница в браузере нужна** как общее веб-управление FuntiDesk; ЛК — её часть. Для веб-управления — отдельный ADR до кода.
5. **ЛК и веб-консоль только смотрят и уменьшают доступ.** Всё, что расширяет доступ (подключиться к компьютеру, добавить в семью, изменить права члена семьи), — только с подтверждением на уже доверенном компьютере; кода из письма для этого мало. Захват почты не должен открывать ни один компьютер.
6. Права членов семьи хранятся и меняются **только на самом компьютере** (ADR-006). ЛК их не видит как управляемые и не меняет.

## 2. Что уже есть в коде

Клиент (`client/`, форк RustDesk 1.5.0, Flutter + Rust):

- Аккаунт upstream выключен: `client/src/flutter_ffi.rs` → `is_disable_account()` всегда `true` (скрыты «Аккаунт», «Заметка», аудит); `client/src/common.rs` → `get_api_server()` пустой. Свой ЛК — **новый** код и свой адрес, upstream-аккаунт остаётся выключенным.
- Ключ устройства: Ed25519, `Config::get_key_pair()`; подпись — `funti_family::sign_message`, проверка — `funti_family::verify`. Семья доверяет этим ключам; ЛК привязывает устройство к аккаунту той же подписью (не новым ключом).
- Семья — у **службы** компьютера (`funti_family.rs`, опция `funti-family`, JSON `Member {id, name, pk, rights}`). Интерфейс никогда не пишет её через кэш настроек: только через IPC службы (`ipc.rs`: `FuntiFamilyAdd/Remove/Rename/Rights`), см. `keep_family`. Синхронизация из ЛК — тоже через службу.
- Свои сообщения в протоколах — номера полей **от 1000** (`client/libs/base/protos/message.proto`, `rendezvous.proto` в `client/libs/hbb_common` и `server/libs/hbb_common`).
- Шаблоны, на которые опираться:
  - сопряжение по коду с сервером: `funti_family.rs` (`offer_code`, `pair_with`), сервер `server/src/funti_pair.rs` (лимиты, TTL, проверка подписи);
  - обновление с проверкой SHA256 и HTTPS только к своему адресу: `client/src/funti_update.rs` (`http()` — редиректы только внутри GitHub, `https_only`);
  - окошко на главном экране: `client/flutter/lib/desktop/widgets/funti_update_notice.dart`;
  - вкладки настроек: `client/flutter/lib/desktop/pages/desktop_setting_page.dart` (`SettingsTabKey`, `_FuntiFamilySettings`);
  - главный экран: `client/flutter/lib/desktop/pages/funti_home_view.dart` (вкладка «Семья» в «Мои устройства»).

Сервер (`server/`, наш hbbs/hbbr, Rust 1.90):

- Работает на `desk.funti.cc` (Contabo, общий с VPN-стеком владельца). Контейнеры `funtidesk-hbbs`, `funtidesk-hbbr`; порты 21115–21117.
- Порт 443 занимает **Caddy VPN-стека** (`/opt/remnawave/caddy/`, Compose-проект `caddy`). Блок `desk.funti.cc` отдаёт статический сайт из `/opt/funtidesk-web/current`. Остальное там — VPN владельца (`remnawave`, Postgres, Valkey): **не трогать**.
- Исходящий порт 25 открыт (проверено 2026-10-13: Gmail, Яндекс), обратная запись адреса `173.249.195.36` → `core.funti.cc`.
- Ресурсы: 2 ядра, ~3 ГБ памяти (≈1,4 ГБ свободно), 25 ГБ диска.
- Развёртывание сервера — только воспроизводимо из репозитория: CI «Server build» → образ с закреплённым SHA → `infra/funtidesk-server/server-release.env` → `scripts/server/deploy.sh` на сервере (`docs/SERVER_DEPLOYMENT.md`). Доступ: root по SSH-ключу; любые изменения на сервере — **с согласия владельца**.

## 3. Предлагаемая архитектура этапа 1 (на согласование с владельцем и Claude)

Это предложение, а не решение: Codex может улучшить, но изменения архитектуры — через ADR (дополнить ADR-009 или новый ADR веб-управления).

**Сервис аккаунтов** — отдельный контейнер `funtidesk-account` рядом с hbbs/hbbr:

- Rust (как сервер): `axum` + SQLite (`rusqlite`/`sqlx`), без Postgres VPN-стека. Данные — в своём томе, резервная копия по `docs/SERVER_DEPLOYMENT.md` («Backup»).
- HTTPS через существующий Caddy: **(а)** `desk.funti.cc/api/account/*` → `reverse_proxy` в блоке `desk.funti.cc` (рекомендация) или **(б)** отдельный поддомен. Оба варианта требуют один раз поправить Caddyfile VPN-стека — **нужно разрешение владельца** (вопрос задан 2026-10-13, ответ ещё не получен). Сервис слушает только `127.0.0.1`/сеть Docker, наружу — только через Caddy.
- Клиент обращается **только** к этому адресу, только HTTPS, без fallback и без прокси из настроек (как `funti_update::http()`); адрес зашит в клиент (R-11/R-12: не берётся из конфига, имени EXE, `custom.txt`).

**Почта:**

- Контейнер отправки (Postfix в режиме «только отправка» или аналог) + подпись DKIM (OpenDKIM). Ключ DKIM — только на сервере, не в репозитории. Почта не принимается.
- DNS `funti.cc`: SPF, DKIM, DMARC — **владелец добавляет записи** или даёт доступ (вопрос задан 2026-10-13). До этого — проверка доставки во входящие Gmail, Яндекса, Mail.ru.
- Письмо: только код, срок, «если это не вы — ничего не делайте». Без ссылок для входа.

**Данные** (минимум; без имени, телефона, платёжных данных):

- `accounts(id случайный, email, created_at, disabled)`;
- `devices(account_id, funti_id, name, pk, version, last_seen, bound_at)` — привязка: устройство подписывает ключом устройства сообщение `funtidesk-account-v1\nbind\n<account_id>\n<funti_id>\n<nonce>`; сервер проверяет подпись тем же `pk`, что знает hbbs для этого ID (как `verify_offer` в ADR-008);
- `sessions(token_hash, account_id, device_or_browser, created_at, expires_at, revoked_at)` — у клиента только случайный токен, на сервере только хэш;
- `challenges(id, email_hash, code_hash, attempts, expires_at, scope)` — один ожидающий на устройство/браузер (уникальный индекс по `scope` для `pending`), повторный заменяет прежний;
- `family_copy(account_id, funti_id, members_json, updated_at)` — копия списков семьи для пункта (а); источник истины — устройства.

**Вход** (как вход мастера в проекте Nails, его ADR-005 «Login challenge», но код из письма): 6 цифр, 5 минут, 5 попыток; ограничения частоты на адрес, устройство, почтовый адрес; при превышении — одинаковый ответ; в журналах нет кода, токенов и адреса почты целиком; «Выйти» и «Выйти на всех устройствах» отзывают сессии сразу.

**Пункт (а):** после входа устройство привязывается (подпись), отдаёт список своих устройств аккаунта и копию семьи; на новом компьютере «Мои устройства» показывает устройства аккаунта. **Добавить устройство в семью из ЛК нельзя** без подтверждения на доверенном компьютере (решение 5) — на этапе 1 достаточно показа.

**Пункт (д):** «Убрать из семьи» в ЛК → сервер ставит отметку; доверенные компьютеры аккаунта при следующем обращении получают её и убирают член семьи **через свою службу** (уменьшение доступа — без подтверждения). На всех компьютерах аккаунта — уведомление «Устройство … убрано из семьи через личный кабинет». Новый вход в ЛК — тоже уведомление.

**Клиент:** экран входа (почта → код), «Личный кабинет» в настройках (вход/выход, список устройств, «Выйти на всех устройствах», «Убрать из семьи»), устройства аккаунта на главном экране. Новые FFI — по образцу `main_funti_*`; новые ключи переводов — `funti-account-*` в `src/lang/en.rs`, `ru.rs`, `template.rs`.

## 4. Правила работы (обязательно)

- `AGENTS.md` (корень) и `client/AGENTS.md` (минимальные изменения в upstream-файлах, тонкие хуки, своя логика — в своих модулях `funti_*`).
- Fail closed: ЛК недоступен → FuntiDesk работает как сейчас (ID, пароль, семья на устройствах); ЛК не становится обязательным ни для чего.
- Никаких внешних сервисов и runtime-обращений, кроме своего адреса; обновить `docs/NETWORK_ALLOWLIST.md`.
- Никаких секретов в репозитории (DKIM, токены, пароли SMTP).
- **Имя владельца нигде** — ни в README, ни в документах, примерах, макетах, интерфейсе, коммитах-описаниях (включая короткие формы и латиницу; логин GitHub — только в технических URL). Нейтральные слова: «член семьи», «сын», «ноутбук владельца». Владелец просил трижды.
- Документация — на русском, простыми словами; английский — только идентификаторы.
- Каждое изменение upstream-файла — строка в `docs/FUNTIDESK_PATCHES.md`; новый `funti-*` ключ — в трёх файлах переводов.
- Приёмка — только end-to-end на реальных клиентах (`AGENTS.md`, «Подход к приёмке»); отчёт — `docs/reviews/<дата>-<тема>-acceptance.md`.
- Мерж в `main`, релиз и любые изменения на сервере — **с согласия владельца** (он обычно отвечает «делай»).

## 5. Сборка, CI, релиз

- Windows-сборка: `scripts/windows/bootstrap.ps1` (один раз), затем `scripts/windows/build-baseline.ps1` (`-PortablePack` — ещё и `FuntiDesk-portable.exe`). Rust 1.75 для клиента, Flutter 3.24.5, мост flutter_rust_bridge 1.80.1 под Flutter 3.22.3 (генерируется сборкой — новые FFI появляются в Dart только после неё). После сборки откатить `client/flutter/pubspec.lock` и `pubspec.yaml`.
- Сервер: `server/`, Rust 1.90, тесты `cargo test` (см. `.github/workflows/server-build.yml`).
- CI: «FuntiDesk CI» (`ci.yml`) на каждом PR; «UI Windows artifact» и «Android APK» — на ветке релизов.
- **Релиз Windows:** ветку `claude/rustdesk-fork-planning-324gyk` перемотать на `origin/main` и отправить; CI публикует релиз `1.5.0-ft.N` (`N` = число коммитов). **Не отправлять туда, пока идёт сборка Windows** (`cancel-in-progress` отменит её). Перед релизом — раздел сверху в `docs/WHATS_NEW.md` (его показывает окошко «Вышла новая версия»).
- Номера сборок и обновление: ADR-007; кнопка обновляет любую копию на месте.

## 7. Открытые вопросы к владельцу (до кода сервера)

1. Маршрут HTTPS: `desk.funti.cc/api/account/*` (рекомендация) или отдельный поддомен — и разрешение один раз поправить Caddyfile VPN-стека.
2. DNS `funti.cc`: кто добавляет SPF/DKIM/DMARC.
3. Адрес отправителя писем (например, `no-reply@funti.cc`).
4. Сайт и веб-кабинет: переносить ли `web/` в `main` (воспроизводимость из репозитория, `AGENTS.md` п. 8) или держать отдельной веткой/репозиторием.

## 8. Замечания к сайту desk.funti.cc (просмотр 2026-10-13, Claude)

1. **FAQ «Как работает семья?»** говорит, что «настройка отдельных разрешений и двусторонние видеокадры представлены как макет». Неверно с `1.5.0-ft.12857`: права членов семьи есть в клиенте (ADR-006), двусторонний видеозвонок — с этапа 2 звонков (ADR-005).
2. **«Скачать для Windows» и «Тестовый Android APK»** ведут на общий список релизов, где вперемешку Windows, Android и серверные сборки. Лучше: Windows — `releases/latest` + команда установки + `FuntiDesk-portable.exe`; Android — на фильтр `funtidesk-android`; упомянуть обновление кнопкой в программе.
3. **Демо главного окна:** «Постоянный доступ» в клиенте стоит сразу под паролем (с 2026-10-12), а в демо — после «Скопировать ID и пароль». Нет окошка «Вышла новая версия», нового окна настроек, «Права» в меню члена семьи.
4. **Названия демо-устройств** по-английски («Home PC», «Work Laptop», «Test phone», «Test Android») на русской странице; «Test …» звучит как черновик. Предложение: «Домашний компьютер», «Ноутбук», «Телефон», «Мамин компьютер».
5. **`web/README.md`** называет источником правды ветку `michailr/m3-windows-ui-redesign` и файлы `funti_design.dart`, `connection_page.dart` — их больше нет; актуальны `main`, `funti_home_view.dart`, `funti_theme.dart` (FAQ на сайте уже ссылается правильно).
6. **Воспроизводимость:** сайт собирается из ветки, которая не сливалась с `main` (см. раздел 7, п. 4).

## 9. Критерии приёмки этапа 1

- Вход по почте: письмо приходит во входящие Gmail/Яндекса/Mail.ru; код одноразовый, 5 минут, 5 попыток; повторный вход заменяет прежний; лимиты частоты; одинаковые ответы на неверный/истёкший код и неизвестную почту.
- Новый компьютер после входа видит свои устройства аккаунта и семью (пункт а).
- «Убрать из семьи» в ЛК убирает устройство на всех компьютерах аккаунта и показывает уведомление (пункт д).
- Захват почты (вход в ЛК с чужого компьютера): видно устройства, **нельзя** подключиться, добавить в семью, изменить права.
- ЛК недоступен (сервис остановлен): FuntiDesk подключается, семья работает.
- Сетевой захват клиента: обращения только к адресам `docs/NETWORK_ALLOWLIST.md`.
- Отчёт приёмки в `docs/reviews/`, раздел в `docs/WHATS_NEW.md`, обновлены ADR-009, ROADMAP, `FUNTIDESK_PATCHES.md`.
