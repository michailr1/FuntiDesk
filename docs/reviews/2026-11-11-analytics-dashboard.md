## CrowdSec — реализован и проверен пакетами

Исходно access log уже читался, GET/401 Basic распознавался как auth_fail (offline GET/200 — не auth_fail). Но bouncer обрабатывал только INPUT, поэтому Docker HTTPS обходил enforcement. #131 добавил own chain, scoped forwarding и идемпотентный drop-in существующего bouncer; исходная INPUT-защита сохранена. Никаких новых контейнеров, API-ключей, сервисов или внешних интеграций.

Первый live-тест реально создал http-generic-bf alert/decision, но не заблокировал HTTPS. Причина подтверждена: Docker DNAT выбирает другую сеть Caddy, match по account-IP имеет нулевой counter. Это не объявлялось успешной приёмкой. Исправление #136 принято и влито; рабочий source `4d41e831d8edb3c470fe6c699d2c162b3c733ebd`. Правило использует conntrack original destination — проверенный локальный DNS A desk — и original port 443 + DNAT. В GitHub только __PUBLIC_V4__, runtime адрес подставлен на сервере. Совпадение DNS/local interface/DNAT target с одним из IP Caddy проверено перед применением.

Изолированный root-only packet test из репозитория выполнен в unshare --net: собственные sets/таблицы/veth и два дочерних namespace. Точное правило подтвердило block/unblock, сохранность другого original IP, другого original port с тем же DNAT target443, порта80 и non-DNAT. systemd-analyze verify существующего unit + drop-in вернул 0.

Live-приёмка выполнена на **production Caddy/CrowdSec/bouncer**, но источник — временный локальный network namespace с benchmark-адресом; это не внешний интернет-хост и не адрес администратора/DE. Реальные неверные Basic-логины → автоматический http-generic-bf decision → недоступность HTTPS → удаление только тестового решения → возврат 200. Порт80 сохранил baseline. Прямой non-DNAT доступ до и после был закрыт политикой Docker; его неизменность подтверждена, а исключение non-DNAT из нового правила доказано изолированным тестом. Первоначальное ошибочное ожидание 200 для прямого Docker-пути исправлено на сравнение baseline, без изменения защитных правил.

Отдельный контролируемый decision подтвердил блокировку после restart только firewall-bouncer, ровно один jump и возврат 200 после unban. Временные child processes/veth/netns и собственные тестовые decisions удалены, отсутствие проверено. CrowdSec, Caddy, Docker, API и VPN для установки не перезапускались. Сервис CrowdSec, bouncer и analytics timer active.

## Ограничения, откат и следующий шаг

IP-ban ограничен публичным HTTPS общего Caddy; firewall не различает URL, поэтому заблокированный IP не откроет и другие сайты на этом 443. VPN-порты, 80/8442 и прочие forwarded-потоки новым jump не охватываются. Это не URL-изолированный HTTP-bouncer. Caddy сейчас публикуется только IPv4; новая forwarding-защита относится к IPv4. При появлении IPv6 publication нужны отдельное правило/тест. После смены публичного IPv4 надо повторно проверить и отрендерить original-destination rule. Docker/host reboot ради теста не выполнялись; unit dependency валидирована, restart/idempotency bouncer проверены live.

Закрытые snapshots/receipts: updates/dashboard-18b84414a и updates/crowdsec-021 под /opt/funtidesk-account/. Исходный bouncer config сохранён; при установке были предусмотрены автоматический возврат конфига/drop-in и удаление собственного jump при ошибке. Для полного отката следовать ACCOUNT_DEPLOYMENT: удалить только собственное правило/drop-in, вернуть список chains, restart bouncer; чужие decisions/INPUT/sets не очищать. Для UI — прежний принятый source и штатный publish; копии прежнего HTML/source сохранены, DB не менять.

Серверная задача #128 принята самостоятельно и выполнена. Следующий шаг — владелец оценивает новый UI; новых сборов телеметрии и изменений клиента этот этап не вводит.
