## DNS и публичный HTTP

До изменения Cloudflare API и два независимых публичных резолвера подтвердили единственную прежнюю SPF без исходящего IPv4 Core и отсутствие TXT `funtidesk202610._domainkey.funti.cc`.

Изменена **существующая** SPF TXT `funti.cc`:

```text
v=spf1 mx a:funti.cc ip4:172.245.108.154 ip4:173.249.195.36 include:sendinblue.com ~all
```

Повторное чтение Cloudflare API подтвердило тот же record ID, единственную SPF и прежний TTL; затем новое значение подтвердили оба публичных резолвера. Другие TXT и MX не изменялись. DKIM пока не добавлен: требуется публичное значение уже существующего Core key из `/opt/funtidesk-account/dns-records.json`; новый ключ не создаётся.

DMARC остаётся `v=DMARC1; p=none`. A `desk.funti.cc` и `core.funti.cc` указывает на Core. PTR `173.249.195.36` при этой проверке вернул NXDOMAIN у обоих резолверов; это расходится с прежним хендофом и требует проверки фактического исходящего SMTP IP/PTR перед приёмкой доставки. Публичные `/account/` и API ещё возвращают `404`, основной сайт — `200`.

## Локально доказанная ошибка SMTP

Снова получен закреплённый artifact `11922857734` исходного `a42f05fa`. `prepare-desk.py --verify-only` подтвердил ZIP, внутренние checksums, classic/OCI IDs и provenance; загруженные локально три образа сверены с release manifest. Это не повторная подготовка Core.

На исходном mail image, с теми же ограничениями и отдельной internal-сетью:

| Очередь | Результат |
| --- | --- |
| Named volume со штатным корнем `0755` | Postfix работает, SMTP banner доступен из peer-контейнера |
| Пустой bind mount с корнем root:root `0700` | Exit 1: `postsuper: fatal: scan_dir_push: open directory defer: Permission denied` |
| Тот же bind mount после изменения только корня на `0755` | Тот же контейнер запускается, SMTP banner доступен |

Изначальный prepare создавал именно второй вариант, тогда как старый smoke использовал первый. Исправлен helper подготовки нового каталога с явным `chmod 0755`, независимым от umask. Smoke теперь использует настоящий пустой bind mount под umask `077`, проверяет root:root `0755` и закрытый подкаталог `0700`. Тестовые ключи/контейнеры/сети/очередь удаляются; наружу письма не отправляются. Причину фактического текущего состояния Core ещё нужно подтвердить чтением до точечного исправления.

## Ревью активации

Исправлены проверка checksum исходного backup, сверка действующего Caddy с исходным Compose/образом/mounts/физическими сетями и разделение фаз отката. HTTPS проверяется с ограниченными повторами, откат — отдельной проверкой прежнего сайта. Marker фиксирует source tools и binary source раздельно. Публичное переключение требует всех серверных предпосылок хендофа.

Реальный локальный smoke также выявил ошибку диагностического BusyBox `nc`: закрытие stdin могло дать exit 0 без HTTP-ответа, а ожидание завершения с открытым stdin — timeout. Проверка живого API включена в smoke, чтобы unit tests не скрывали этот случай.

Клиент исправлен: получает ограниченный HTTP-ответ до закрытия stdin, затем завершает процесс в пределах общего deadline. Полный smoke прошёл на закреплённых образах: оба приватных GET через Caddy-image client, подписанное письмо в изолированной очереди, вход, независимая копия, CLI restore со сбросом прежней сессии, отказ постороннему sender и при остановленном DKIM, отсутствие тестовых секретов в logs. Также прошли 30 unit tests активации, Compose/Caddy validation и Python syntax/diff checks. Unit tests включены отдельным job `deployment-tools` в Account checks; это ещё не результат удалённого CI нового commit.
