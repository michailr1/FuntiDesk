# Личный кабинет: проверка серверного API

Дата: 2026-10-13. Статус: локальная проверка реализации, **не E2E-приёмка первого этапа**.

Реализован отдельный сервис `account/` на Rust 1.90, SQLite и `axum`. Вход использует почтовый код, отдельный контекст, HMAC и атомарное расходование; сессии — случайные токены с хэшами и серверным отзывом. Привязка компьютера требует Ed25519-подпись его зарегистрированного ключа. Семейные копии содержат только данные для показа, без прав. Отзывы хранятся независимо от почтовых сессий и подтверждений компьютеров.

Сервис получает ключ hbbs через новый необязательный Unix socket, без mounts базы и приватного ключа. В существующих файлах сервера добавлены только объявление модуля и один вызов при запуске. Без переменной включения прежний путь сохраняется; ошибка resolver не завершает hbbs.

## Фактические проверки

- `cargo fmt --manifest-path account/Cargo.toml -- --check` — успешно.
- `cargo clippy --manifest-path account/Cargo.toml --all-targets --locked --offline -- -D warnings` — успешно, без предупреждений в account.
- `cargo test --manifest-path account/Cargo.toml --locked --offline` — 14 API-проверок успешно: контекст и одноразовость кода при гонке, пять попыток и срок, замена challenge и независимые лимиты, cookie/Origin/CSRF, отзыв всех сессий, подмена ключа и повтор nonce, границы аккаунтов, копии без прав и повторная доставка удаления, смена ключа и сохранение лимитов после перезапуска SQLite; добавлены независимость одновременных source nonce, смена ID с прежним ключом, сохранение общего почтового бюджета при локальных отказах и запрет обхода лимита сессий нативным токеном в браузерном режиме.
- `cargo test --manifest-path account/Cargo.toml --locked --offline --test registry` — 2 проверки успешно: протокол Unix socket и отказ при отсутствии/невалидном ответе.
- `cargo check --manifest-path server/Cargo.toml --lib --locked` — успешно. Предупреждения существующего upstream-кода не исправлялись в этом изменении.
- `cargo test --manifest-path server/Cargo.toml --locked --offline --test account_identity --test tcp_signaling` — 5 проверок успешно: настоящий hbbs возвращает зарегистрированный ключ, сломанный socket не мешает регистрации, сохранились TCP-регистрация/доставка, UDP-доставка и heartbeat.

Проверки socket сначала не могли запуститься из-за запрета sandbox на локальные сокеты (`Operation not permitted`). После предоставления сетевого доступа они успешно повторены. Это ограничение среды не скрыто пропуском тестов.

Новый workflow `Account checks` запускает проверки account, resolver и TCP-сигнализации, собирает отдельный артефакт с SHA-256. Для исходного серверного коммита `bf15eb592b84a5cd7d7ad7ed6474fea4e1021cb5` успешно завершились [Account checks](https://github.com/michailr1/FuntiDesk/actions/runs/38472085719) и [FuntiDesk CI](https://github.com/michailr1/FuntiDesk/actions/runs/38472085560). Для последующих исправлений результат удалённого CI проверяется отдельно.

При проверке исправлены четыре дефекта: новый source nonce отменял вызов службы до проверки подписи; повторная привязка того же ключа сохраняла старый адрес; отклонённые запросы расходовали общий бюджет писем; нативный токен в браузерном cookie мог обойти предел сессий. Для ограниченного списка доставок добавлен явный `has_more`.

## Регрессионная поверхность и ограничения

Изменены существующие `server/src/lib.rs` и `server/src/rendezvous_server.rs`: только включение необязательного внутреннего resolver. Внешние rendezvous/relay-протоколы и семейное доверие клиента не изменены. Кэш UI не получает путь импорта серверных копий в семью. Исходный server lockfile и тестовая SQLite-база не входят в изменение.

В тестах почтовые задания принимаются очередью в памяти; внешние письма не отправлялись. Настоящий SMTP/DKIM, Caddy и DNS не развёрнуты. Клиентские IPC, защищённый токен, фоновое применение отзывов, экран кабинета и сайт ещё не реализованы. Поэтому серверный ack пока проверяется моделью клиента, а не настоящей службой Windows.

До выпуска остаются согласованная поставка и резервное копирование, безопасное восстановление с сохранением последних отзывов, сроки хранения и удаление аккаунта, интеграция клиента и сайта, доставка во входящие Gmail/Яндекса/Mail.ru, два реальных Windows-клиента и браузер, offline-удаление и сетевой захват. На рабочем сервере изменений нет.
