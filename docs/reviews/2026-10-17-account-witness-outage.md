# Недоступность кабинета: отключён независимый witness

**Устранён 2026-10-17:** владелец отменил witness по [ADR-013](../ADR-013-core-only-account.md); кабинет работает с SQLite на Core. Возвращение witness на DE не выполнялось. [Результат обновления](2026-10-17-core-only-account.md). Ниже исходная диагностика.

Дата проверки: 2026-10-17. Пользователь сообщил ошибку «Кабинет сейчас недоступен» в Windows.

## Установленная причина

- Core API и witness-relay запущены с прежними проверенными образами, без рестартов. В журнале API повторяется `account database maintenance failed`.
- Независимый адрес `https://de.funti.cc:8447/v1/witness` отказывает в TCP-соединении; fresh signed Head probe не проходит (`Witness transport failed`).
- На DE отсутствуют действующие witness-контейнеры, каталог `/opt/funtidesk-account-witness` и TLS timer. Они сохранены в `/root/funtidesk-witness-removed-2026-10-15/`; время изменения каталога — 2026-10-15 16:27:49 МСК. Кто и по какому решению вывел сервис из работы, этой проверкой не установлено.
- Архивная цепочка проверена по HMAC всех 16 records, digest последней зашифрованной копии совпал. Архивный Head revision 19 целиком совпадает с последней подтверждённой отметкой Core; машинный ключ совпадает. Текущая основная revision — 21, её нельзя объявлять подтверждённой до связи с witness.
- Архивный TLS-сертификат действует до 2026-12-03. Отказ вызван отсутствием работающего сервиса, а не истечением этого сертификата.

Статические `/account/` и bootstrap отвечают `200`, запросы session/library без токена — `401`; это не доказывает готовность авторизованных операций. При необходимости независимого подтверждения кабинет отказывает по ADR-011, вместо публикации неподтверждённых результатов.

## Следующее действие

Уточнить, должен ли DE оставаться без FuntiDesk: найденный каталог явно помечен `removed`, поэтому прежнее размещение нельзя молча вернуть поверх возможного решения владельца. Если DE разрешён, вернуть существующие данные и TLS-конфигурацию, проверить image/source, mounts, сети и свободный 8447, запустить прежний witness без `witness-init`, затем проверить fresh signed Head с Core и завершение pending operation. Не менять ключи/namespace и не восстанавливать старую основную SQLite-копию. При отказе от DE потребуется отдельное решение о новом независимом размещении.

В рамках диагностики выполнены только чтения; рабочие конфигурации, данные и контейнеры не изменялись. Живое исправление и повторная проверка кабинета ещё не выполнены.
