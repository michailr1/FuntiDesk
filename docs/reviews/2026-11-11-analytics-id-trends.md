Дата: 2026-11-11. Продолжение серверной аналитики #128 по поручению владельца; самостоятельная приёмка, клиентские ветки не менялись.

Реализовано и опубликовано #139 из main `40678ca2b8fe206f6ab1542b0652c1829227d677`: нулевые даты скрыты в графике и раскрываемой таблице сохранённых подключений; пустой период отображает объяснение. Недельное сравнение остаётся календарным. Добавлен график «Новые регистрации ID» за 30 дат с недельным сравнением, по created_at текущих записей peer в hbbs. Это регистрации ID, не люди/установки; смена ID в существующей записи сохраняет дату, что подписано. В HTML только агрегаты, ID/ключи не выводятся. На production чтением подтверждены поле created_at и text storage; миграций/записей в рабочие DB не было.

Проверено: 13 тестов (6 snapshot, 2 publish, 5 dashboard), включая UTC-даты, группировку и границы 30 дней/будущее, неизменность SQLite, пустые/нулевые ряды. Chromium 1440/390/320: три непустых дня в синтетическом графике и таблице, новый ID chart, отсутствие overflow/page errors/внешних запросов; desktop просмотрен визуально. Preview в репозитории помечен как демонстрационный.

Поставка: чистый закреплённый analytics source, все 13 тестов повторены на desk, штатный funtidesk-analytics.service успешно обновил страницу. Реальный закрытый HTML проверен: нулевых дат/строк в истории нет, ID chart есть, 401/200/no-store сохранены; timer active. Все контейнеры сохранили ID; Caddy, CrowdSec, VPN, API, пароли/путь и клиент не менялись. Реквизиты/production-метрики не публиковались.

Закрытый rollback snapshot: /opt/funtidesk-account/updates/id-trends-40678ca2b, сохранены source.before, index.before.html, receipt.json. При ошибке был предусмотрен возврат прежнего source и штатный publish; он не потребовался. Для отката повторить этот порядок, DB не менять. Ограничение: ряд hbbs показывает сохранившиеся записи, не полную историю изменений ID; крайние даты могут быть неполными.
