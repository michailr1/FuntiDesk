# Передача файлов без подключения экрана (#67)

По жалобе владельца убрана обязательная предварительная видеосессия. На начальной форме видно «Передать файлы»: проверка полей, один ввод ID/пароля и прямой файловый вход. Пароль сразу очищается в обеих формах, промежуточная форма пароля во время входа скрыта. WebCodecs/VP9 для файлов не нужны. При открытии из активного экрана остаются обязательными его ID/peer key и отдельная авторизация на компьютере; секрет экрана не сохраняется для переиспользования. Pagehide/завершение закрывают также files-only и очищают локальный выбор/Blob; старое восстановление видео отменяется при явном переходе к files-only.

Самостоятельный режим запрашивается только явным null вместо parent key: прежние подписи закреплённого сервера/ID компьютера и его ephemeral key проверяются до отправки password proof. Потерянный/некорректный parent key не превращается в fallback; активное видео требует точного совпадения ключа. Проверку пароля/PermissionInfo.File выполняет компьютер. Протокол, хранение секретов и ограничения передачи прежние; уточнение ADR-015 внесено.

Проверки: 22 unit/native-crypto теста, включая запрет неявного standalone при undefined/коротком parent key. Реальный production main.js (с тестовым trust anchor) в зашифрованном fixture без VideoDecoder/EncodedVideoChunk: начальная кнопка, валидация до сети, только conn_type=FILE_TRANSFER и один login, одноразовое потребление пароля, скачивание, pagehide без recovery-записи. Отказ File, повреждённые подписи сервера и компьютера завершаются без доступа; до повреждённой identity парольный proof не уходит. Старые двухпанельные upload/ACK/download bytes/отмена/права и полный video/phone/reload сценарий проходят. Поставка console-only из main, главная/кабинет/API v4 сохраняются; источник/публичные проверки/откат — в PR. Физический Windows/iPhone ещё проверяет владелец, #67 открыт.
