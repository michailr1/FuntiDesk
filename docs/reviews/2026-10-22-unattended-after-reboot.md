# Доступ без входа после перезагрузки (Windows, P1)

Дата: 2026-10-22. Компьютер MINIPC, служба `FuntiDesk` (LocalSystem, Automatic). Ветка `michailr1/nifty-noether-mos7q6` от `main` `6aa036d`.

**Статус: причина установлена по журналам; исправлена настройкой на MINIPC и проверена владельцем (подключение к экрану входа после перезагрузки работает). Новая сборка с миграцией и журналами службы на Windows не проверена.**

## Причина (по журналам MINIPC)

**Установленный узел работает в режиме UDP-сигнализации, а не TCP.** Во всех настройках MINIPC сохранено явное `disable-udp = "N"`: у службы (`ServiceProfiles\LocalService\...\FuntiDesk2.toml`) и у пользователей `micha` и `share`. Явное значение перекрывает значение по умолчанию ADR-004 (`DEFAULT_SETTINGS`: `disable-udp = Y`, `client/src/common.rs`; поиск в `Config::get_option`: сохранённое значение выше значения по умолчанию). Все запуски `--server` в журналах с 2026-10-19 по 2026-10-22, включая запуски после RDP, — `start udp: desk.funti.cc:21116`, ни одного `start tcp`.

В режиме UDP узел регистрируется и виден «в сети», но запросы на подключение (`PunchHole`/`RequestRelay`) приходят входящим UDP. Именно такая сеть описана в ADR-004: регистрация проходит, входящие запросы теряются. Журнал `--server` второй загрузки (17:14:38–17:38:22, сессия 1, экран входа): регистрация с 17:14:45, за 24 минуты дошёл один запрос (17:22:29, `Punch tcp hole … Nothing connected … None of 1 punches was met`), остальных нет.

Совпадение с RDP: при смене сессии служба запускает новый `--server`, у него новый UDP-сокет и новое сопоставление NAT, и некоторое время входящие запросы проходят. Это объясняет, почему помогало переподключение RDP, но тоже в режиме UDP и ненадёжно.

Откуда взялось `"N"`, по журналам не видно. Его пишет переключатель «Отключить UDP» в «Дополнительно» (`desktop_setting_page.dart`: при выключении — `'N'`), значение переносится из старого профиля при миграции (приёмка 2026-10-08) и попадает в службу при синхронизации настроек из интерфейса.

## Попутно найденные дефекты службы (исправлены в ветке)

1. 14:35:44, первая загрузка: консольная сессия на миг пропала (`0xFFFFFFFF`), служба закрыла работающий `--server` и пыталась запустить новый в несуществующей сессии (`os error 87`, `No process winlogon.exe`). Теперь запуск в «нет сессии» не выполняется, работающий `--server` не закрывается; при `0xFFFFFFFF` проверка, жив ли `--server`, не пропускается.
2. `LaunchProcessWin` терял код ошибки `CreateProcessAsUserW` (перезаписывался `CloseHandle`).
3. Служба не писала, почему и в какую сессию запускает `--server`, с каким PID и почему он завершился. Добавлено (`client/src/platform/windows/funti_service.rs`); `rendezvous_mediator.rs` пишет полученные `PunchHole`/`RequestRelay` (не чаще раза в 10 с).
4. Попутно в журналах: интерфейс пользователя из сессии 1 (не SYSTEM) отклоняется главным IPC `--server`, работающего в другой сессии (`Rejected unauthorized connection … expected_session_id=2/3`). Это поведение upstream при RDP, на доступ извне не влияет; отдельная задача при необходимости.

Сторожевой перезапуск незарегистрированного `--server` из первого коммита убран: узел был зарегистрирован, перезапуск оставляет тот же режим UDP.

## Исправление причины

Немедленно, без новой сборки: на MINIPC в FuntiDesk «Настройки → Дополнительно → Отключить UDP» включить. Значение `Y` совпадает со значением по умолчанию, поэтому ключ удаляется из настроек; служба перезапускает подключение к серверу (`ipc.rs`, сравнение `disable_udp`). Проверка: в журнале `server\FuntiDesk_rCURRENT.log` строка `start tcp: desk.funti.cc:21116`.

В коде (решение владельца 2026-10-22 — «TCP по умолчанию»): `client/src/common.rs`, `funti_drop_stale_udp_choice()`. При первом запуске новой сборки каждый процесс (служба/`--server` и интерфейс пользователя) один раз удаляет сохранённое `disable-udp = "N"` и отмечает это опцией `funti-tcp-default-applied`. TCP остаётся значением по умолчанию, а не жёстким запретом (R-15): «N», выбранное пользователем позже, сохраняется. Проверка: `scripts/ci/test-r15-safe-defaults.sh`.

**Проверено владельцем на MINIPC 2026-10-22:** после включения «Отключить UDP» — `start tcp: desk.funti.cc:21116`, `keep_alive: 30000ms`; после перезагрузки подключение к экрану входа без входа и без RDP — «всё отлично, работает».

## Журналы

- Служба: `C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\FuntiDesk\log\service\`
- `--server`: `C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\FuntiDesk\log\server\`

Пишутся до входа пользователя, читаются PowerShell от администратора (Проводник без повышения прав сообщает «не удаётся найти»). Строки службы начинаются с `FuntiDesk service:`.

## Сборка

Windows-сборка: workflow `R21 Windows clean build` (`workflow_dispatch`, без публикации релиза), артефакт `funtidesk-windows-x64-<sha>`. Релиз не выпускался.

## Установка на MINIPC (вручную, через RDP `minipc\admin`)

1. Убедиться, что RDP-доступ `minipc\admin` работает. Не завершать RDP-сеанс, не перезагружать без готовности.
2. Резервная копия: `Copy-Item 'C:\Program Files\FuntiDesk' 'C:\FuntiDesk-backup-<дата>' -Recurse` и запись `& 'C:\Program Files\FuntiDesk\FuntiDesk.exe' --version`.
3. Скопировать журналы (выше).
4. `sc stop FuntiDesk`; дождаться остановки; закрыть FuntiDesk в сеансе (трей).
5. Скопировать содержимое артефакта поверх `C:\Program Files\FuntiDesk`.
6. `sc start FuntiDesk`; проверить в журнале службы строку `FuntiDesk service: --server started, pid …`.

## Откат

`sc stop FuntiDesk` → `Remove-Item 'C:\Program Files\FuntiDesk' -Recurse` → `Copy-Item 'C:\FuntiDesk-backup-<дата>' 'C:\Program Files\FuntiDesk' -Recurse` → `sc start FuntiDesk` → `--version` совпадает с записанной. Конфигурация (ID, ключи, семья) хранится в профиле SYSTEM и при замене папки не меняется.

## Известные ограничения

- Если консольная сессия пропадает, служба не перезапускает `--server`, пока сессия не появится (работающий `--server` при этом остаётся).
- Компьютеры семьи с сохранённым `disable-udp = "N"` исправляются только после обновления на сборку с миграцией.
