# Избранное, история и браузерный клиент — реализация в PR #50

Дата: 2026-10-15. [ADR-012](../ADR-012-account-sync-and-browser.md). Это проверяемый draft; API v3 и полный кабинет с избранным/историей включены на Core. Браузерный кандидат доступен для живой проверки на `https://desk.funti.cc/connect/`; пароль проверяет принимающий компьютер. Пользователь подтвердил наличие двух Windows-компьютеров для следующей живой приёмки.

## Реализовано

- API и схема v3: избранное с проверкой версии, история успешных исходящих подключений с идентификатором события, очистка с новым поколением. До 128 избранных компьютеров и 1000 событий за 90 дней. Пароли, локальные настройки и семейные права не передаются.
- Веб-кабинет: добавление и удаление избранного, история и очистка, переход к отдельному экрану подключения. Имена выводятся текстом.
- Windows: по уточнению владельца синхронизация автоматически работает после входа, включая сохранённую сессию. Отдельного переключателя нет; обычная вкладка избранного и звёздочки используют список аккаунта, без входа сохраняется локальный путь. Существующее локальное избранное загружается только отдельной командой пользователя. Старые недавние подключения не импортируются.
- Новые успешные исходящие сеансы экрана записываются после PeerInfo. Аккаунт и поколение захватываются до подключения; события не переходят в другой аккаунт. До 128 отложенных событий хранятся у actor; при выходе, смене входа или отзыве сессии очередь очищается. Временный отказ API допускает последующую отправку; события из очищенного поколения отбрасываются. Изменения избранного без доступного API отклоняются с ошибкой, без скрытого перезаписывания серверного списка.
- Свой браузерный клиент `/connect/`: временный/постоянный пароль, проверка подписанных ID/ключей, обмен v1 с разными ключами направлений, VP9 через WebCodecs, экран, мышь/клавиатура и завершение. WSS закреплён на нашем домене; внешние relay-адреса из ответа не используются. Почтовая сессия и семейная копия не авторизуют сеанс.

## Проверки

- Локально прошли 39 Rust-тестов account и Clippy с `-D warnings`, включая изоляцию аккаунтов, конфликт избранного, повтор истории, очистку, запрет чужого исходного устройства и CSRF новых маршрутов.
- Миграция существующей v2-базы сохранила аккаунт и действующую сессию; повторное открытие сохранило v3 и избранное. Открытие больше не понижает `user_version` между транзакциями миграций.
- Восстановление из последней настоящей зашифрованной witness-копии в тестовом окружении сохранило избранное, пустую историю и её новое поколение.
- Настоящий Chromium с локальным API прошёл вход/выход, cookie/Origin/CSRF, безопасный вывод, добавление избранного, конфликт, историю, повтор события и очистку без возврата старого события. Запросы браузера привязаны к локальному fixture, письма наружу не отправляются.
- Контрольные значения браузерной криптографии побайтово совпадают с `client/libs/hbb_common/src/tcp.rs`. Проверены обе подписи, неверные ключи/ID, парольный challenge, упаковка сессионного ключа и раздельные направления шифрования.
- Chromium с синтетическим протокольным компьютером показал настоящий декодированный VP9-кадр, отправил мышь и клавиатуру, прекратил ввод при запрете, отклонил неверные пароль/ключ, завершил сеанс без пароля в поле и без localStorage/sessionStorage. Проверка проходит с ограничивающей CSP и без JavaScript `unsafe-eval`.
- Отдельный фрагмент WSS/Caddy прошёл локальную проверку и включён штатным browser-only helper из source `508b1d0e99f0`. Публичные HTML/JS побайтово совпали с проверенной сборкой; после включения полного кабинета отдельно сверены SHA256 его HTML/JS и `/connect/`, все ответы `no-store`; оба WSS upgrade вернули `101` для нашего Origin и `403` для чужого. Cookie и Authorization не проксируются в hbbs/hbbr. API, кабинет, DB v2, mail/relay/серверы и ключи сохранены. [Действующая конфигурация](../ACCOUNT_DEPLOYMENT.md#действующий-публичный-caddy).
- Сканер секретов проверяется с default rules. Исключены только точные публичный trust anchor и пять названий функций/констант закреплённого libsodium в двух указанных файлах. Синтетический canary в том же пути bundle по-прежнему обнаруживается; целые файлы не исключены.

CI source `8aec8df11cfa` прошёл: [Account checks](https://github.com/michailr1/FuntiDesk/actions/runs/38734692324), [Browser client checks](https://github.com/michailr1/FuntiDesk/actions/runs/38734692420), [FuntiDesk CI](https://github.com/michailr1/FuntiDesk/actions/runs/38734692391). [Чистая Windows-сборка source `a3187565`](https://github.com/michailr1/FuntiDesk/actions/runs/38738885770) успешно завершилась, включая Windows storage test; client tree с автоматической синхронизацией закреплён этим source. Протокольный fixture и успешная компиляция не заменяют приёмку на двух настоящих клиентах.

## Изменённые существующие пути

- `account/src/{lib,web,store}.rs`: подключение отдельного модуля/маршрутов, миграция v3 и удаление истёкших метаданных. Старые маршруты авторизации и подписанного удаления не переписаны.
- `client/src/funti_account{,_windows}.rs`: новые команды, отдельные списки и очередь рядом с существующим actor; токен по-прежнему у службы под DPAPI.
- `client/src/client/io_loop.rs`: только захват аккаунта до исходящего соединения и событие после успешного PeerInfo, под Windows. Аутентификация и передача сеанса не изменены.
- `client/src/flutter_ffi.rs`: чтение избранного аккаунта для существующей вкладки и адресные строки без PeerConfig для ещё не посещённых компьютеров. Конфигурация, пароли и доверенные ключи не создаются и не изменяются.
- Три существующих Dart-экрана со звёздочками вызывают отдельный helper для избранного; режим без аккаунта/неподдерживаемая платформа используют старые локальные API. Свой account widget показывает списки без переключателя синхронизации. Остальные платформы сохраняют локальный путь.
- Таблицы локализации дополнены новыми ключами; имеющиеся переводы не переписаны. Добавлены отдельные browser sources, статическая сборка и необязательные конфигурации развёртывания.

## Оставшаяся приёмка

1. Установить проверенную Windows-сборку ниже на оба компьютера: обновить UI и службу, иначе старый actor не знает новых команд.
2. API v3 и полный webroot уже развёрнуты из проверенных CI-образов: API source `508b1d0e99f0`, tools/web `8aec8df11cfa`. Подтверждены миграция v3, signed witness, публичные HTTP-коды и сохранение ключей/остальных контейнеров. Новое проверочное письмо пришло во Входящие Gmail; интеграция скрывает OTP, поэтому публичный вход и изменение избранного в этой итерации ждут кода владельца. Локальный полный сценарий прошёл. Откат API на v2 запрещён.
3. Один аккаунт на двух компьютерах: без дополнительного включения добавить и удалить избранное на разных клиентах, проверить новые подключения в истории и очистку. Отдельно — выход, смена аккаунта и работа без API.
4. Базовое браузерное подключение с временным паролем, экраном, мышью и клавиатурой подтверждено владельцем. Остаются постоянный пароль при включённом постоянном доступе, неверный пароль, запрет ввода и завершение на компьютере. Проверить native-native соединения и сохранение идентичностей.

Семейный браузерный вход, звук, файлы, буфер обмена, Safari/телефон и добавление браузерных сеансов в историю этим этапом не приняты. M3 остаётся открытым.


## Порядок живой проверки на двух компьютерах

Использовать один проверенный Windows runtime из указанного clean-build run на обоих компьютерах. Закрыть прежнюю UI и обновить установленный FuntiDesk штатной установкой; новая UI рядом со старой службой не является проверкой новой реализации. Сохранить ID и существующие конфигурации, ключи/семью не сбрасывать.

1. Войти в аккаунт на обоих компьютерах: синхронизация уже действует, отдельного включения нет. Проверить также восстановленный вход после перезапуска новой службы. Локальные звёздочки импортируются только отдельной кнопкой.
2. Добавить компьютер в избранное на первом, обновить списки на втором и в веб-кабинете; удалить на втором и проверить первый. При одновременном изменении ожидается сообщение о конфликте и предложение обновить, а не скрытая перезапись.
3. Выполнить успешное исходящее подключение первого ко второму. Проверить одну новую запись истории в обоих клиентах/кабинете. Неверный пароль не создаёт историю успешного сеанса. Очистка истории должна остаться после повторного обмена.
4. На втором компьютере открыть `/connect/` в Chrome/Edge, ввести ID первого и его временный пароль. Проверить экран, мышь, клавиатуру, потерю фокуса, запрет ввода и завершение на принимающем компьютере. Повторить с постоянным паролем только если этот доступ явно включён на первом.
5. Убедиться, что неверный пароль отклоняется, а один вход в кабинет без пароля компьютера не открывает экран. Проверить обычное native-native подключение после веб-сеанса.
6. Выйти: локальные подключения остаются доступны; списки другого аккаунта не отображаются. Коды почты, пароли и session cookies в отчёт не включать.

До получения результатов владельца эти пункты остаются непроверенными; успешные fixture и CI не заменяют их.

Изменение автоматической синхронизации проверено Chromium с настоящим локальным API: изменение избранного и новое событие истории от нативного клиента появились в веб-кабинете без нажатия «Обновить»; после выхода автоматические чтения прекратились. Новая Windows-сборка source `a3187565` прошла, архив и все 91 runtime-файл проверены; предыдущая сборка с opt-in отменена и не подтверждает новое поведение. Вкладка избранного сверяется с активным списком в существующем 20-секундном UI-цикле, даже когда раздел аккаунта закрыт.

Граница изменений автоматизации: `funti_account_windows.rs` убирает команду opt-in, сохраняя чтение прежнего состояния; `funti_account.rs` не подменяет ещё не загруженный список аккаунта локальным; собственный account widget теряет переключатель. Helper `common/funti_library.dart` и тонкий вызов из существующего 20-секундного цикла `funti_home_view.dart` обновляют обычную вкладку избранного при изменении ID, без отдельного таймера/копии состояния. Web использует прежние API/CSRF и обновляет списки в фоне. Бинарные файлы API, протокол подключения и Windows-служба на компьютерах владельца пока не заменялись.

Автообновление веб-кабинета включено на Core штатным static-only updater из source `3c327e5f4e19`; публичный JS совпал с manifest, `200/no-store`. API, DB, другие контейнеры, Caddyfile/env/image/SSL volume/сети не менялись. Три теста updater проверили переключение, возврат при отказе readiness и запрет изменённого Compose до переключения. Повторно прошли все 39 Rust-тестов account; форматирование двух изменённых Rust-файлов проверено.
