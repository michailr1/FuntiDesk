# Избранное, история и браузерный клиент — реализация в PR #50

Дата: 2026-10-15. [ADR-012](../ADR-012-account-sync-and-browser.md). Это проверяемый draft; синхронизация ещё не включена в production. Отдельный кандидат браузерного клиента уже доступен для живой проверки на `https://desk.funti.cc/connect/`; старые кабинет, API и DB v2 сохранены. Пользователь подтвердил наличие двух Windows-компьютеров для следующей живой приёмки.

## Реализовано

- API и схема v3: избранное с проверкой версии, история успешных исходящих подключений с идентификатором события, очистка с новым поколением. До 128 избранных компьютеров и 1000 событий за 90 дней. Пароли, локальные настройки и семейные права не передаются.
- Веб-кабинет: добавление и удаление избранного, история и очистка, переход к отдельному экрану подключения. Имена выводятся текстом.
- Windows: явный переключатель синхронизации в своём кабинете. При включении обычная вкладка избранного и звёздочки используют список аккаунта; при выключении сохраняется прежний локальный путь. Существующее локальное избранное загружается только отдельной командой пользователя. Старые недавние подключения не импортируются.
- Новые успешные исходящие сеансы экрана записываются после PeerInfo. Аккаунт и поколение захватываются до подключения; события не переходят в другой аккаунт. До 128 отложенных событий хранятся у actor; при выходе, смене входа или выключении синхронизации очередь очищается. Временный отказ API допускает последующую отправку; события из очищенного поколения отбрасываются. Изменения избранного без доступного API отклоняются с ошибкой, без скрытого перезаписывания серверного списка.
- Свой браузерный клиент `/connect/`: временный/постоянный пароль, проверка подписанных ID/ключей, обмен v1 с разными ключами направлений, VP9 через WebCodecs, экран, мышь/клавиатура и завершение. WSS закреплён на нашем домене; внешние relay-адреса из ответа не используются. Почтовая сессия и семейная копия не авторизуют сеанс.

## Проверки

- Локально прошли 39 Rust-тестов account и Clippy с `-D warnings`, включая изоляцию аккаунтов, конфликт избранного, повтор истории, очистку, запрет чужого исходного устройства и CSRF новых маршрутов.
- Миграция существующей v2-базы сохранила аккаунт и действующую сессию; повторное открытие сохранило v3 и избранное. Открытие больше не понижает `user_version` между транзакциями миграций.
- Восстановление из последней настоящей зашифрованной witness-копии в тестовом окружении сохранило избранное, пустую историю и её новое поколение.
- Настоящий Chromium с локальным API прошёл вход/выход, cookie/Origin/CSRF, безопасный вывод, добавление избранного, конфликт, историю, повтор события и очистку без возврата старого события. Запросы браузера привязаны к локальному fixture, письма наружу не отправляются.
- Контрольные значения браузерной криптографии побайтово совпадают с `client/libs/hbb_common/src/tcp.rs`. Проверены обе подписи, неверные ключи/ID, парольный challenge, упаковка сессионного ключа и раздельные направления шифрования.
- Chromium с синтетическим протокольным компьютером показал настоящий декодированный VP9-кадр, отправил мышь и клавиатуру, прекратил ввод при запрете, отклонил неверные пароль/ключ, завершил сеанс без пароля в поле и без localStorage/sessionStorage. Проверка проходит с ограничивающей CSP и без JavaScript `unsafe-eval`.
- Отдельный фрагмент WSS/Caddy прошёл локальную проверку и включён штатным browser-only helper из source `508b1d0e99f0`. Публичные HTML/JS побайтово совпали с проверенной сборкой; оба WSS upgrade вернули `101` для нашего Origin и `403` для чужого. Cookie и Authorization не проксируются в hbbs/hbbr. API, кабинет, DB v2, mail/relay/серверы и ключи сохранены. [Действующая конфигурация](../ACCOUNT_DEPLOYMENT.md#действующий-публичный-caddy).
- Сканер секретов проверяется с default rules. Исключены только точные публичный trust anchor и пять названий функций/констант закреплённого libsodium в двух указанных файлах. Синтетический canary в том же пути bundle по-прежнему обнаруживается; целые файлы не исключены.

Чистая Windows-сборка и CI выполняются; их итоговые ссылки и статус будут добавлены после завершения. Протокольный fixture и успешная компиляция не заменяют приёмку на двух настоящих клиентах.

## Изменённые существующие пути

- `account/src/{lib,web,store}.rs`: подключение отдельного модуля/маршрутов, миграция v3 и удаление истёкших метаданных. Старые маршруты авторизации и подписанного удаления не переписаны.
- `client/src/funti_account{,_windows}.rs`: новые команды, отдельные списки и очередь рядом с существующим actor; токен по-прежнему у службы под DPAPI.
- `client/src/client/io_loop.rs`: только захват аккаунта до исходящего соединения и событие после успешного PeerInfo, под Windows. Аутентификация и передача сеанса не изменены.
- `client/src/flutter_ffi.rs`: чтение избранного аккаунта для существующей вкладки и адресные строки без PeerConfig для ещё не посещённых компьютеров. Конфигурация, пароли и доверенные ключи не создаются и не изменяются.
- Три существующих Dart-экрана со звёздочками вызывают отдельный helper для избранного; выключенная/неподдерживаемая синхронизация использует старые локальные API. Свой account widget показывает переключатель и списки. Остальные платформы сохраняют локальный путь.
- Таблицы локализации дополнены новыми ключами; имеющиеся переводы не переписаны. Добавлены отдельные browser sources, статическая сборка и необязательные конфигурации развёртывания.

## Оставшаяся приёмка

1. Проверенная Windows-сборка; оба компьютера должны использовать новую UI и службу, иначе старый actor не знает новых команд.
2. Развёртывание совместимого API v3, нового webroot и проверенного полного Caddyfile с дополнительной сетью. Сохранять существующий account override, ключи, namespace и witness. Старый API v2 не открывает новую базу: откат не выполняется восстановлением старой SQLite-копии.
3. Один аккаунт на двух компьютерах: включить синхронизацию, добавить и удалить избранное на разных клиентах, проверить новые подключения в истории и очистку. Отдельно — выход, смена аккаунта и работа без API.
4. Настоящий браузер → Windows: временный пароль, постоянный при включённом постоянном доступе, неверный пароль, запрет ввода и завершение на компьютере. Проверить native-native соединения и сохранение идентичностей.

Семейный браузерный вход, звук, файлы, буфер обмена, Safari/телефон и добавление браузерных сеансов в историю этим этапом не приняты. M3 остаётся открытым.
