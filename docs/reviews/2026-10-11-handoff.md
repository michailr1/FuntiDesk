## 3. Что дальше (по приоритету, решения владельца — в ROADMAP M4)

1. ✅ (2026-10-11, в коде, ждёт живой проверки) **«Камера на той стороне недоступна»** — звонящему вместо бесконечного «ожидания изображения», когда камера не даёт кадров (запрет антивируса/политики). Сервер уже завершает видеосервис с ошибкой через 10 с; ошибка не доходит до клиента.
2. ✅ (2026-10-11, `1.4.9-ft.<число коммитов>`) **Своя нумерация сборок** (сейчас у всех 1.4.9 upstream), например `1.4.9-ft.<номер CI>` — первый шаг к обновлению.
3. **«Обновить» кнопкой** в клиенте, затем **удалённое обновление** при подключении (проверка версии той стороны, кнопка «Обновить», без подтверждения там, видимое уведомление). ADR-007 принят 2026-10-11: пока без подписи релизов (риск захвата аккаунта GitHub принят), дальше — реализация.
4. **Android на телефоне владельца:** приёмка APK, затем свой мобильный интерфейс только по утверждённому макету.
5. **Макеты на утверждение:** https://claude.ai/artifact/66WPFWgtxN28oLgG2AzvH2 — экран передачи файлов, главный экран Android, «О программе» с цитатами и котом. Ответов владельца пока нет.
6. Мелочи из ROADMAP: метка P2P/relay в окне сеанса, семья в установленном режиме (служба) не проверена, видео в обе стороны на двух компьютерах с камерами не проверено, скриншоты входящего звонка и «просит помощи» для README.

## 4. Как работать на этой машине (важно)

- **Сборка:** `scripts/windows/build-baseline.ps1` (≈20–25 мин; `-PortablePack` — ещё и один exe). Запускать с отключённой песочницей и с Python владельца первым в PATH (см. память `windows-machine-toolchain`). После сборки — `git checkout -- client/flutter/pubspec.lock`.
- **Быстрая проверка на втором компьютере:** собрать локально → `Compress-Archive` в `C:\funtidesk-accept\*.zip` → владелец забирает через «Только передать файлы» и ставит поверх. CI-релиз — около 45 мин и отменяется следующим пушем (`cancel-in-progress`).
- **Логи CI** без входа в GitHub не читаются; Android-workflow при ошибке кладёт лог в pre-release `funtidesk-android-ci-log`.
- **Защита Claude Code (auto mode):** запрещены запись в `main` (`git merge`/`push`) и сохранение учётных данных (`gh auth login` → «Unauthorized Persistence»). `gh` лежит в `C:\Tools\gh\bin\gh.exe`, не авторизован. Слияние PR делает владелец в браузере; либо владелец сам добавляет правила через `/permissions` в интерактивном `claude`.
- **Песочница:** записи сессии в `%APPDATA%` не видны процессам вне неё; для управления FuntiDesk/чтения его журналов — команды с отключённой песочницей (разрешено владельцем).
- **Скриншоты окна:** `PrintWindow` (скрипт в scratchpad), а не `CopyFromScreen` — иначе поверх окна попадает чужое; headless Edge 154 не сохраняет скриншоты — для SVG → PNG `skia-python`.
- **Heredoc в Bash съедает обратные слэши** — Python-патчи с `\` писать файлом.
- **`client/.gitignore` игнорирует `*png`** — новые PNG добавлять `git add -f`.
- **Ноутбуки владельца:** `440171008` (desktop-86ud4s7, камера работает); `28604993` (второй ноутбук владельца, корпоративный Kaspersky Endpoint Security блокирует FuntiDesk камеру и микрофон — не дефект FuntiDesk). Владелец работает удалённо, у компьютера с репозиторием его нет.

## 5. Правила, о которых легко забыть

- Документация по-русски; FUNTIDESK-метки в коде upstream; fail closed; без секретов в репозитории.
- Свои поля протокола — номера от 1000.
- Не переодевать upstream-экраны: новый интерфейс — только по утверждённому макету.
- Пароли владельца не вводить и не хранить; одноразовые пароли FuntiDesk, которые он присылает, — только для текущей проверки.
- Слияние в `main`, подпись релизов, `applicationId` Android, изменения на сервере — решения владельца.
