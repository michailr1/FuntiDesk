# Автоматический перенос локальных списков в аккаунт

Владелец подтвердил восстановление кабинета и потребовал синхронизацию без отдельной кнопки импорта. Основание — уточнение [ADR-012](../ADR-012-account-sync-and-browser.md) от 2026-10-17. Код PR #50 объединён с актуальным main `4815b32b4`: сохранены работы Клода по NAT/смене сети, текущему relay toggle, праву семьи менять настройки, приёмке релиза 12930 и границам инфраструктуры. Конфликты были только в AGENTS.md и историческом статусе ADR-011; требования main сохранены, действующий ADR-013 учтён.

## Поведение

- После готовности аккаунта фоновая задача в существующем UI runtime переносит локальное избранное, без открытия кабинета и подтверждения. Привязка устройства нужна для переноса истории, но не блокирует избранное. Обычная звёздочка у компьютера продолжает менять избранное аккаунта. В кабинете удалены отдельный ввод ID, кнопка добавления и диалог импорта.
- Запоминается последний перенесённый локальный список отдельно для аккаунта и Windows-профиля. Повторный вход/перезапуск не возвращает удалённую на другом устройстве запись. Добавления/удаления, сделанные в локальном избранном без входа, передаются при следующем входе. Версия списка и проверка точного account_id остаются обязательными.
- Новые успешные исходящие подключения уже записываются автоматически существующим hook. Дополнительно один раз переносятся до 1000 локальных недавних записей за последние 90 дней: только ID, название и время обновления локальной записи, которое может отличаться от точного времени сеанса. Никакие peer config, пароли, ключи или права не отправляются. Общее избранное видно в обычном списке избранного и кабинете; общая история — в кабинете. Обычные локальные «Недавние» и их удаление не меняются.
- Идентификатор старого события стабилен для аккаунта/источника/ID/даты, поэтому повтор не создаёт дубль. Сервис ставит такой event_id в существующую очередь, не дублирует уже ожидающую запись, источник по-прежнему определяет сам по привязке. После очистки истории старый локальный список не импортируется заново. Сбои сети/лимиты оставляют перенос для следующего фонового чтения статуса.
- UI получает кешированный ответ статуса до переноса. Операции ограничены существующими лимитами API; API, база, SMTP, Caddy, серверы и рабочее развёртывание не меняются.

## Проверки и поверхность изменения

Прошли 27 Rust-тестов, fmt и Clippy `-D warnings`. Добавлены две регрессионные проверки: объединение избранного/удаления и идемпотентность/границы/состав переноса истории. Существующие API-тесты проверяют версии списков, разные аккаунты, повтор событий и очистку истории.

Изменены только account UI bridge (фоновый перенос и локальный прогресс), account protocol (две проверяемые функции для списков), Windows account actor (публичный ID привязки в статусе и метаданные старой истории в существующей очереди), Flutter account panel (удаление ручных действий) и RU/EN пояснение. Общие пути remote connection, peer cards, локальных «Недавних», NAT и семейных прав в этом изменении не меняются; изменения main включены отдельным merge-коммитом.

Чистая Windows-сборка и реальная проверка автопереноса на двух компьютерах ещё ожидаются. Успешные локальные проверки не закрывают M3. Старый CI-кандидат `ed52dc8a2` содержит только исправление часов, без актуального main и этого изменения; его не следует использовать для приёмки нового поведения.
