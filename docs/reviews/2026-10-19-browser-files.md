# Файлы в веб-консоли (#67)
Реализация плана #85 и ADR-015: панель файлов в desktop/телефонном меню, отдельный подписанный/шифрованный файловый вход к тому же ID/ключу, пароль компьютера с автозаполнением и немедленной очисткой. Кабинет и recovery-хранилище не участвуют. Папки, отправка File.slice, скачивание raw/Zstandard, прогресс, отмена, явное сохранение Blob; один файл до 50 МБ, без замены/рекурсивных папок/докачки. Исходный wire/Windows/сервер не меняются.

Файловая авторизация получает исходную папку автоматически от компьютера: лишний ReadDir не посылается, чтобы не перепутать ответы без ID. Подтверждения записи/конфликты обрабатываются штатными digest/send_confirm/done; отправленные байты не считаются успехом до ACK. Валидируются имена, IDs/индекс, размеры/окно/frame до распаковки, итоговый размер и done; late frames отменённого ID игнорируются. Socket drain ограничивает очередь. Запрет File скрывает кнопку/закрывает панель независимо от Keyboard; основной сеанс не получает новых прав.

Проверки: 16 unit/native-crypto тестов; libzstd-векторы 0/4096/131072 байт и негативные frame/размеры/имена; подписанный зашифрованный файловый fixture с неправильным паролем/ключом/отзывом права. Chromium UI проверяет реальные download bytes, upload/ACK, конфликт, отмену, layout 320/390/844 px, очистку Blob URL и запрет кнопки. Прежний полный браузерный протокол видео/жестов/reload также проходит. Десять тестов статической поставки включают console-only/rollback и сохранение главной/кабинета на v4. Новых сервисов и CDN нет; одна закреплённая MIT-зависимость включена в notices. CI в очереди не считается success.

Поставка — только консоль из main (`--console-only`), без миграции API и без смены главной/кабинета. Откат — прежний webroot штатным helper-порядком. Настоящие Windows/iPhone ещё не проверены: #67 остаётся открытым до отправки фото/скачивания в «Файлы», отмены и запрета права на физических клиентах. Фоновая передача Safari не гарантируется; при обрыве пользователь начинает заново. Планировавшиеся протокол и UI укладываются в один небольшой прикладной PR, без промежуточной поставки неиспользуемого кода.
