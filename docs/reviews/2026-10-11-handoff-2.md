## 2. Что сделано 2026-10-11

1. **«Камера на той стороне недоступна»** (`f69d696`). Видеосервис камеры при сбое (камера без кадров 10 с, запрет антивируса/политики) теперь отправляет каждому звонящему upstream `MessageBox` `custom-nocancel-info` / `funti-call-title` / `funti-call-camera-unavailable` — один раз, пока камера снова не даст кадр. Протокол не менялся. Код: `client/src/server/video_service.rs` (`funti_tell_camera_unavailable`), `service.rs` (`subscriber_ids`), `lang/{ru,en,template}.rs`; ADR-005 «Последствия». Владелец решил оставить, хотя причина на второй ноутбук владельца — антивирус: сообщение нужно звонящему.
2. **Нумерация сборок `1.4.9-ft.N`** (`30f1fc3`). `N` = `git rev-list --count HEAD`, считает `client/build.rs` → `crate::FUNTI_BUILD`; в shallow-клоне и без git — `0`. Видно в «О программе», строке состояния главного экрана, `--version`. `crate::VERSION` остаётся `1.4.9` (по нему upstream проверяет возможности другой стороны и пишет реестр установщика). В workflow Windows и Android checkout с `fetch-depth: 0`.
3. **ADR-007 обновления** (`97a9793`). Решение владельца: пока **без подписи релизов**, доверие как у `install.ps1` (только релизы `michailr1/FuntiDesk` по HTTPS, SHA256, 2FA на GitHub); риск захвата аккаунта GitHub принят. Подпись ключом вне GitHub — путь усиления. Там же устройство «Обновить» и удалённого обновления.

## 3. Что делать на Windows (по порядку)

1. **Собрать** ветку `build-baseline.ps1` (полный клон, не shallow). Проверить:
   - «О программе» и строка состояния показывают `1.4.9-ft.<N>`, где `N` = `git rev-list --count HEAD`, а не `0`;
   - повторная сборка без изменений не пересобирает библиотеку из-за `build.rs` (он следит за `.git/HEAD` и ref ветки).
2. **Проверить камеру:** звонок с ноутбука владельца на второй ноутбук владельца (антивирус блокирует камеру) — через ~10 с у звонящего «Камера на той стороне недоступна…», голос работает. Обычный звонок на компьютер с рабочей камерой — сообщения нет. Скриншот — в отчёт приёмки `2026-10-08-pr12-windows-acceptance.md` (новый раздел).
3. Если всё зелёное — предложить владельцу PR `ccr-b0e9b2c1-ihszsw` → `main` (слияние делает владелец).
4. **Пункт 3 хендофа — код обновления по ADR-007**:
   - CI: класть `funtidesk-version.txt` (`1.4.9-ft.N`) в Windows-релиз и в `SHA256SUMS.txt`;
   - «О программе»: «Проверить обновления» / «Обновить» — скачать, сверить SHA256, заменить файлы как `install.ps1`, перезапуск; в установленном режиме — через службу; любая ошибка — сообщение, установленная версия не трогается;
   - затем удалённое обновление: своё поле версии в протоколе (номер от 1000), кнопка в окне сеанса управления, на той стороне видимое окно «FuntiDesk обновляется…».
5. Остальное из раздела 3 предыдущего хендофа: Android на телефоне владельца, макеты на утверждение, мелочи ROADMAP.
