# Передача файлов из браузера (#67): план

Владелец 2026-10-19 попросил реализовать файлы сейчас. Эта работа самостоятельна относительно ещё открытого #66: не объединяет кабинет и консоль, не меняет главную. Существующий протокол и компьютер остаются источником авторизации и прав.

1. Кнопка «Файлы» в обычном интерфейсе и меню телефона. Встроенная панель, список папок/обычных файлов, выбор файла/фото, скачивание, прогресс и отмена. Запрет PermissionInfo.File скрывает кнопку и закрывает файловый канал.
2. Нужен **отдельный файловый сеанс**: Connection обрабатывает FileAction только при LoginRequest.file_transfer. Повторяются подписанный handshake, проверка того же ID/ключа, новый challenge и пароль; conn_type=FILE_TRANSFER. На первом открытии панели — пароль компьютера (системное автозаполнение), после авторизации он сразу стирается; хранение секретов восстановления не расширяется. Закрытие панели/основного сеанса закрывает файловое соединение.
3. ReadDir/FileDirectory — просмотр. FileAction.receive + FileResponse.block/done — отправка; FileAction.send + send_confirm + FileResponse.dir/digest/block/done — скачивание. IDs/номер файла/размеры проверяются; один файл за раз, без рекурсивных папок, удаления и переименования. Ссылки/неизвестные типы не скачиваются.
4. До 50 MiB на файл, блок до 128 KiB несжатых данных. Отправка читает File.slice по одному блоку и ждёт освобождения WebSocket buffer; скачивание ограничивает память и размер Blob. Отмена посылает штатный cancel и отбрасывает поздние блоки; обрыв не выдаётся за успех. Успех загрузки только после ответа компьютера, скачивания — после done и точного совпадения размера.
5. Компьютер автоматически использует Zstandard для текстов и других сжимаемых файлов. Ни CompressionStream Safari, ни прежние зависимости его не декодируют. Простейший вариант — один небольшой pure-JS decoder `fzstd@0.1.1` (MIT), закреплённый lock-файлом и включённый в notices. Никакого CDN/нового процесса/сетевой загрузки кода; выход распаковки и входной блок жёстко ограничены. Конкретное решение фиксируется в ADR-015 до включения в сборку.
6. iPhone: готовый Blob выдаётся отдельным пользовательским нажатием «Сохранить», через ссылку download (при необходимости системное «Поделиться → Сохранить в Файлы»). Без File System Access API, service worker и IndexedDB. Blob URL освобождается при следующей передаче/закрытии панели. Не обещаем удержание передачи в фоне Safari.
7. Одноимённый файл: не перезаписывать молча. При конфликте — сообщение и выбор другого имени (в первой версии без замены/докачки). Имена из API через textContent; запрет traversal/NUL/разделителей/NTFS reserved names на отправке.

Проверки: отдельный подписанный/шифрованный файловый handshake, неверный пароль/ключ/право, отмена и отзыв права посреди операции, raw/zstd/нулевой файл, точные байты, конфликт имени, чужие ID, превышение размера/распаковки, разрыв/поздние блоки и уничтожение Blob URL. Затем реальный Windows-компьютер и Safari/iPhone (включая «Домой»); Chromium не заменяет эту приёмку. Поэтапные PR до ~400 прикладных строк: протокол/тесты, UI/интеграция. Новый API/сервер/Windows-релиз не нужны.
