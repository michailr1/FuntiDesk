# Резервная копия и восстановление кабинета

Действует [ADR-013](ADR-013-core-only-account.md): основная SQLite-база находится на Core, независимого witness нет.

Перед обновлением остановить только API, сделать согласованную SQLite-копию с `integrity_check` и сохранить её в закрытом каталоге `0700`, файл `0600`. SQLite Online Backup учитывает committed WAL; копирование одного файла работающей базы без WAL не является согласованной копией. Ключ аккаунта сохраняется отдельно, не печатается и не попадает в Git. Существующий `backup-desk.py` шифрует секреты кабинета и данные hbbs, но не заменяет копию account DB.

Для восстановления остановить API и сохранить его текущие DB/WAL/SHM. Проверить выбранную копию на отдельном пути, совместимость схемы и наличие исходного account key; затем переключить базу и запустить совместимый API. Не совмещать старые WAL/SHM с восстановленной базой. Восстановленная копия отражает состояние на момент её создания, включая список сессий и отзывы: возврат старой копии не гарантирует сохранения более поздних изменений. Обновление v3→v4 выполняется на нынешней базе, а не восстановлением старой.

Команды witness-init, witness, witness-relay и restore независимой копии удалены. DE для запуска и восстановления кабинета не требуется. Новые backup-сервисы не вводятся.
