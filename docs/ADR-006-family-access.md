# ADR-006: Семейный доступ — сопряжение устройств и вход без пароля

**Статус:** принято владельцем 2026-10-08 (решения по правам, хранению и порядку работ). Этапы 1 (сопряжение и вход) и 2 («Попросить помощи») реализованы; сопряжение, вход члена семьи с «Принять» и доставка запроса помощи проверены 2026-10-09 на двух компьютерах.
**Дата:** 2026-10-08.
**Связано:** ADR-005 (звонки, этап 3), `docs/ROADMAP.md` («Попросить помощи»), `docs/SECURITY.md`, ADR-002 (custom-client trust), R-12.

## Проблема

Сейчас к компьютеру подключаются по ID и паролю, который надо продиктовать. Для семьи это неудобно (маме нужно найти и прочитать пароль) и небезопасно в обратную сторону: имя и ID звонящего сообщает его собственный клиент, принимающая сторона их не проверяет, поэтому «звонит Миша» может написать кто угодно.

## Решения владельца (2026-10-08)

1. Сопряжённый член семьи подключается без пароля. ~~На принимающей стороне всегда нажимают «Принять»~~ — пересмотрено владельцем 2026-10-09 после проверки: «Принять» делало члена семьи слабее человека с паролем. Теперь управление, файлы и терминал — **без подтверждения** (как постоянный пароль, но только для сопряжённых устройств); на **звонок** по-прежнему нужно ответить.
2. Список семьи хранится **на каждом устройстве**. Сервер FuntiDesk ничего о семьях не знает, аккаунтов нет.
3. Сначала семейный доступ, затем Android-клиент.

## Решение

### Идентичность устройства

У каждого устройства уже есть постоянная пара ключей Ed25519 (`Config::get_key_pair`), открытый ключ зарегистрирован на `hbbs`, и при каждом подключении принимающая сторона подтверждает его (`SignedId`, проверка по ключу сервера, R-12). Семейный доступ использует эту же пару ключей, новых секретов нет.

### Сопряжение (один раз)

1. На компьютере А (например, у мамы): «Мои устройства» → «Семья» → «Добавить в семью» → «Показать код». Служба А выдаёт одноразовый код из 6 цифр, действующий 10 минут.
2. Человек на А диктует код (по телефону) или помощник видит его сам.
3. На компьютере Б (помощник): «Добавить в семью» → «Ввести код»: ID компьютера А и код. Клиент Б подключается к А обычным защищённым соединением (А подтверждает себя ключом, проверенным сервером), вместо пароля отправляет код, свой открытый ключ, имя и подпись своего ключа над вызовом этого соединения.
4. Служба А проверяет код (одноразовый, срок, общий счётчик неудачных попыток с паролем — защита от перебора) и подпись, сохраняет Б в свой список семьи, отвечает своим именем и закрывает соединение.
5. Клиент Б сохраняет А в свой список: ID, имя и открытый ключ А, проверенный при подключении.

Сопряжение взаимное: после него и А, и Б могут звонить друг другу без пароля.

### Вход члена семьи

- Клиент Б при подключении к А, который есть в его списке семьи, просит свою службу подписать вызов соединения (`challenge` из `Hash`) вместе с ID А и ID Б. Подпись уходит в `LoginRequest` вместо пароля.
- Служба А находит Б в своём списке по ID и проверяет подпись сохранённым ключом. Совпало — это член семьи: управление, файлы и терминал открываются сразу; звонок (сеанс камеры) ждёт «Ответить» на А. Не совпало или Б нет в списке — обычный путь с паролем (fail closed).
- Подпись привязана к вызову конкретного соединения и к ID А — повторить её для другого соединения или другого компьютера нельзя.
- Удалить из семьи — взаимно (решение владельца 2026-10-09): клиент отправляет другой стороне подписанное «выйти из семьи» (`LoginRequest.funti_family_unpair`, поле 1004), та удаляет запись о нём; затем запись удаляется у себя. Попросить удалить можно только себя (подпись своим ключом). Если другая сторона не в сети — удаление только у себя, и интерфейс прямо говорит, что там вы остаётесь в семье, пока вас не удалят.
- Имя члена семьи — локальное: при сопряжении обе стороны могут задать понятное имя («Мама»), его видно только на своём устройстве; переименование — в меню строки семьи.

### Хранение

Список семьи — опция службы `funti-family`: JSON-массив `{id, name, pk}` (`pk` — открытый ключ Ed25519 в base64). Читает и меняет его только служба своего устройства; интерфейс — через IPC. Подпись делает служба (у неё ключ устройства и в портативном, и в установленном режиме).

### «Попросить помощи» (этап 2)

Кнопка на компьютере А отправляет запрос **одному выбранному** члену семьи (решение владельца 2026-10-09: без рассылки «всем»; если в семье один человек — без выбора) без нового серверного канала: клиент А подключается к Б (вход по семье) с типом «запрос помощи»; у Б появляется уведомление «Мама просит помощи» с «Подключиться». Подключение Б к А в ответ на свежий запрос принимается без «Принять» на А (мама только что попросила сама), по одноразовому разрешению, как встречное видео в ADR-005. Б должен быть в сети; если никого из семьи нет в сети — понятное сообщение и обычный путь «продиктуйте ID и пароль».

### Протокол

- `LoginRequest.funti_family_pair` (поле 1001): код, открытый ключ, подпись.
- `LoginRequest.funti_family_proof` (поле 1002): подпись входа.
- `LoginResponse.funti_family_paired` (поле 1001): имя принимающей стороны после сопряжения.

Номера от 1000 зарезервированы за FuntiDesk. Клиенты, не знающие этих полей, их игнорируют: старый клиент А попросит у Б пароль. Сервер `hbbs`/`hbbr` не меняется.

## Последствия

- Звонящего из семьи нельзя подделать: имя и ID подтверждаются ключом, сохранённым при сопряжении.
- Код сопряжения — новая поверхность атаки: 6 цифр, 10 минут, одноразовый, общие с паролем ограничения неудачных попыток; сопряжение без кода невозможно.
- Переустановка FuntiDesk с новым профилем меняет ключ устройства — сопряжение придётся повторить (вход по семье не пройдёт, останется пароль).
- Семья — это неуправляемый доступ для сопряжённых устройств: член семьи может зайти, когда у компьютера никого нет. Поэтому сопряжение только по коду с экрана этого компьютера, удаление — взаимное, а список семьи виден во вкладке «Семья».
