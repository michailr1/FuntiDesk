# ADR-009: Личный кабинет FuntiDesk

**Статус:** черновик, частично решён (2026-10-13). Кода нет. Решения владельца: 2026-10-12 — личный кабинет нужен, свой сервис без закрытой серверной части upstream; 2026-10-13 — назначение кабинета (пункты а и д), страница в браузере нужна как общее веб-управление с кабинетом внутри, **без внешних зависимостей** (Telegram отклонён: «пока лишний»). Открыто: способ входа — раздел «Вход без внешних зависимостей».
**Связано:** ADR-004 (свой сервер), ADR-006 и ADR-008 (семья), ADR-007 (обновления), `docs/SECURITY.md` (R-10…R-15, R-14 — нет чужих API), `docs/ROADMAP.md` («Личный кабинет FuntiDesk»).

## Проблема

Сейчас всё, что человек знает о своих компьютерах, живёт на каждом компьютере отдельно: семья — у службы каждого устройства (ADR-006), недавние и избранные — в настройках клиента. На новом компьютере всё начинается с нуля; список «моих компьютеров» в одном месте не посмотреть; потерянный ноутбук не убрать из семьи с другого устройства.

В upstream это решает сервер аккаунтов RustDesk Server Pro: вход, адресная книга, группы, журнал. Он закрытый и платный; клиент FuntiDesk к нему не обращается (`get_api_server` пустой, `is_disable_account()` = `true`, R-14).

## Что нужно решить владельцу

1. ~~**Зачем кабинет в первую очередь.**~~ Решено 2026-10-13: этап 1 — (а) и (д). Кандидаты (из обсуждения 2026-10-12):
   - а) вход на новом компьютере → сразу видны свои устройства и семья, без кодов;
   - б) список своих устройств в браузере (кто в сети, какая версия, когда был);
   - в) общая адресная книга (кроме семьи — знакомые, которым помогаю по паролю);
   - г) история подключений;
   - д) удалённо убрать устройство из семьи (потерян, продан).
2. **Как входить** — без внешних зависимостей (решение 2026-10-13); варианты — раздел «Вход без внешних зависимостей».
3. ~~**Где кабинет.**~~ Решено 2026-10-13: в клиенте и на странице в браузере; страница — общее веб-управление FuntiDesk, кабинет — её часть.

## Вход без внешних зависимостей (на решение владельца)

Отклонены 2026-10-13: Telegram (внешний сервис, «пока лишний»), вход через Google/Яндекс (внешний поставщик), пароль (забывают и перебирают).

| Вариант | Как | Что нужно | Минусы |
|---|---|---|---|
| **1. Подтверждение со своего устройства** | Аккаунт создаётся на первом компьютере — это его ключ, без почты и пароля. На новом компьютере или в браузере — шестизначное число; на уже вошедшем FuntiDesk — «Войти на <имя>? Число … — Подтвердить». Приём входа Nails (ADR-005 Nails, «Login challenge»), подтверждает наш клиент. | только наш сервер | нужно вошедшее устройство под рукой |
| **2. Коды восстановления** | при создании аккаунта — 8–10 одноразовых кодов, сохранить или распечатать; код открывает аккаунт, если все устройства потеряны | только наш сервер | коды нужно хранить; без устройств и кодов — новый аккаунт (семья на устройствах работает) |
| **3. Ключ доступа (passkey, WebAuthn)** | вход на странице в браузере через Windows Hello, отпечаток или PIN телефона | наш сервер и браузер | только для браузера; в клиенте сложнее |
| **4. Почта через свой SMTP** | код на почту, письма отправляет `desk.funti.cc` | свой SMTP, DNS: SPF, DKIM, DMARC | письма с нового сервера попадают в спам; сама почта всё равно внешняя |

**Предложение:** 1 + 2; 3 — позже, для страницы в браузере. Нет паролей и чужих сервисов; захват почты или чужого аккаунта ничего не даёт.

**Общие правила входа** (как в Nails): вход одноразовый, живёт 5 минут; один ожидающий вход на устройство (уникальный индекс в базе), повторный заменяет прежний; ограничения частоты на адрес, устройство и аккаунт, при превышении — одинаковый ответ «попробуйте позже»; сессия на сервере, у клиента — только случайный токен; «Выйти» и «Выйти на всех устройствах» отзывают сессии сразу; в журналах нет числа сверки, кодов восстановления и токенов.

## Страница в браузере (решение владельца 2026-10-13)

Будет общим веб-управлением FuntiDesk; личный кабинет — её часть (свои устройства, семья, сессии, коды восстановления). Отдельный ADR на веб-управление — до кода; там же — граница: HTTPS только на нашем домене, сессии на сервере, Host/Origin, CSRF для изменений, лимиты (как в Nails ADR-005). Вход на странице — числом с подтверждением в FuntiDesk (вариант 1), позже — ключ доступа (вариант 3).

## Что хранит сервер (предложение)

- Аккаунт: случайный идентификатор, дата создания, хэши кодов восстановления. Без имени, почты, телефона, платёжных данных.
- Устройства аккаунта: ID FuntiDesk, имя, открытый ключ устройства (тот же, что в семье), версия, когда было в сети.
- Семья аккаунта: копия списка, который сейчас хранит служба каждого устройства; источник истины остаётся на устройствах, сервер синхронизирует (добавить/убрать с любого устройства своего аккаунта).
- **Не хранит:** пароли подключения, постоянные пароли, содержимое сеансов, файлы, журнал экрана. Журнал подключений (г) — только «кто, к кому, когда», и только если владелец выберет этот пункт.

## Безопасность (обязательные условия)

- Fail closed: недоступен кабинет — FuntiDesk работает как сейчас (ID, пароль, семья на устройствах); кабинет не становится обязательным для подключения.
- Вход в кабинет не даёт доступа к компьютерам сам по себе: подключение по-прежнему по паролю или через семью с ключами устройств (ADR-006); кабинет только раздаёт устройствам список «кому доверять», подписанный ключом уже доверенного устройства аккаунта.
- Вход в кабинет не открывает компьютеры: добавление устройства в семью через кабинет подтверждается на уже вошедшем устройстве; код восстановления даёт вход в кабинет, но не добавляет устройства в семью без такого подтверждения или без кода семьи (ADR-008).
- Сервер — наш (`desk.funti.cc`), рядом с hbbs/hbbr; данные — в нашей базе; резервная копия и удаление аккаунта — описаны до запуска.
- Протокол — свои сообщения с номерами от 1000 или отдельный HTTPS API на нашем домене; клиент обращается только к нему (без fallback).

## Последствия

- Новый серверный компонент (сервис аккаунтов + база) — отдельное развёртывание, мониторинг и резервные копии (`docs/SERVER_DEPLOYMENT.md`).
- Без внешних зависимостей (решение 2026-10-13): ни почтового сервиса, ни Telegram; всё на `desk.funti.cc`.
- Клиент: экран входа, «Мои устройства» из кабинета, синхронизация семьи; `is_disable_account()` перестаёт быть `true` только для нашего сервиса (upstream-аккаунт остаётся выключенным).
- Объём — несколько этапов; первым предлагается (а)+(д).

## Порядок (предложение)

1. Решение владельца по пунктам «Что нужно решить».
2. ADR дополняется выбранным и становится «принято».
3. Этап 1: сервис аккаунтов, вход выбранным способом, список устройств в клиенте. Этап 2: синхронизация семьи, удалённое удаление. Этап 3: страница в браузере (общее веб-управление, отдельный ADR), журнал — если нужен.
