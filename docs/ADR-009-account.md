# ADR-009: Личный кабинет FuntiDesk

**Статус:** черновик, частично решён (2026-10-13). Кода нет. Решения владельца: 2026-10-12 — личный кабинет нужен, свой сервис без закрытой серверной части upstream; 2026-10-13 — **вход через почту и через Telegram по коду, как в проекте Nails** (его ADR-005, «Login challenge»). Открыто: зачем кабинет в первую очередь (пункт 1) и нужна ли страница в браузере (пункт 3).
**Связано:** ADR-004 (свой сервер), ADR-006 и ADR-008 (семья), ADR-007 (обновления), `docs/SECURITY.md` (R-10…R-15, R-14 — нет чужих API), `docs/ROADMAP.md` («Личный кабинет FuntiDesk»).

## Проблема

Сейчас всё, что человек знает о своих компьютерах, живёт на каждом компьютере отдельно: семья — у службы каждого устройства (ADR-006), недавние и избранные — в настройках клиента. На новом компьютере всё начинается с нуля; список «моих компьютеров» в одном месте не посмотреть; потерянный ноутбук не убрать из семьи с другого устройства.

В upstream это решает сервер аккаунтов RustDesk Server Pro: вход, адресная книга, группы, журнал. Он закрытый и платный; клиент FuntiDesk к нему не обращается (`get_api_server` пустой, `is_disable_account()` = `true`, R-14).

## Что нужно решить владельцу

1. **Зачем кабинет в первую очередь** — от этого зависит всё остальное. Кандидаты (из обсуждения 2026-10-12):
   - а) вход на новом компьютере → сразу видны свои устройства и семья, без кодов;
   - б) список своих устройств в браузере (кто в сети, какая версия, когда был);
   - в) общая адресная книга (кроме семьи — знакомые, которым помогаю по паролю);
   - г) история подключений;
   - д) удалённо убрать устройство из семьи (потерян, продан).
2. ~~**Как входить.**~~ Решено 2026-10-13: почта и Telegram по коду — раздел «Вход».
3. **Где кабинет:** только в клиенте или ещё и страница в браузере.

## Варианты входа

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Почта + код** | вводится адрес, приходит одноразовый код | без пароля, понятно маме | нужен почтовый сервис (отправка писем — внешняя зависимость); письма попадают в спам |
| **B. Вход с другого своего устройства** | на новом компьютере показан QR/код, на уже вошедшем устройстве — «Разрешить» | без почты и паролей, тот же приём, что код семьи (ADR-008) | первое устройство всё равно надо как-то создать (A или C) |
| **C. Сервисы (Google, Яндекс)** | OAuth | привычно | внешний поставщик знает о входах; противоречит духу R-14; сложнее |
| **D. Пароль** | логин и пароль | просто сделать | пароли забывают, их перебирают; хранить хэши на сервере |

**Решение владельца 2026-10-13:** A (почта) и Telegram по коду; C и D — нет. B остаётся как условие безопасности для добавления устройства в семью (раздел «Безопасность»), а не как способ входа.

## Вход (решение владельца 2026-10-13)

Тот же приём, что вход мастера в Nails (ADR-005 Nails, «Login challenge»):

**Через Telegram — сверка числа, без ввода кода.**
1. Клиент FuntiDesk: «Войти через Telegram» → сервер создаёт вход (challenge) и показывает в клиенте шестизначное число и ссылку на бот FuntiDesk.
2. Бот FuntiDesk присылает то же число и кнопку «Подтвердить вход на <имя компьютера>».
3. Человек сверяет число и нажимает кнопку; клиент получает сессию. Вводить код никуда не нужно.
4. Первый вход через Telegram создаёт аккаунт и связывает его с Telegram-аккаунтом (бот знает только числовой Telegram ID).

**Через почту — код в письме.**
1. Клиент: «Войти по почте» → адрес → сервер отправляет письмо с шестизначным кодом.
2. Код вводится в клиенте; совпал — сессия.
3. Почту можно привязать к аккаунту, созданному через Telegram, и наоборот (подтверждение — входом вторым способом из уже вошедшего клиента).

**Общие правила входа** (как в Nails):
- вход одноразовый, живёт 5 минут, у кода — лимит попыток; повторный «Войти» с того же устройства заменяет прежний ожидающий вход (один ожидающий на устройство — уникальный индекс в базе);
- ограничения частоты: на адрес, на устройство, на почтовый адрес и на Telegram-аккаунт; при превышении — одинаковый ответ «попробуйте позже»;
- сессия хранится на сервере, у клиента — только случайный токен; «Выйти» и «Выйти на всех устройствах» отзывают сессии сразу;
- в журналах нет кода, числа сверки, токена сессии и адреса почты целиком;
- неизвестный или заблокированный аккаунт сессию не получает, ответ тот же, что при неверном коде.

## Что хранит сервер (предложение)

- Аккаунт: адрес почты, дата создания. Без имени, телефона, платёжных данных.
- Устройства аккаунта: ID FuntiDesk, имя, открытый ключ устройства (тот же, что в семье), версия, когда было в сети.
- Семья аккаунта: копия списка, который сейчас хранит служба каждого устройства; источник истины остаётся на устройствах, сервер синхронизирует (добавить/убрать с любого устройства своего аккаунта).
- **Не хранит:** пароли подключения, постоянные пароли, содержимое сеансов, файлы, журнал экрана. Журнал подключений (г) — только «кто, к кому, когда», и только если владелец выберет этот пункт.

## Безопасность (обязательные условия)

- Fail closed: недоступен кабинет — FuntiDesk работает как сейчас (ID, пароль, семья на устройствах); кабинет не становится обязательным для подключения.
- Вход в кабинет не даёт доступа к компьютерам сам по себе: подключение по-прежнему по паролю или через семью с ключами устройств (ADR-006); кабинет только раздаёт устройствам список «кому доверять», подписанный ключом уже доверенного устройства аккаунта.
- Потеря аккаунта (захват почты или Telegram) не должна открывать компьютеры: добавление нового устройства в семью через кабинет подтверждается на уже вошедшем устройстве (вариант B), а не одним письмом или одним нажатием в боте.
- Сервер — наш (`desk.funti.cc`), рядом с hbbs/hbbr; данные — в нашей базе; резервная копия и удаление аккаунта — описаны до запуска.
- Протокол — свои сообщения с номерами от 1000 или отдельный HTTPS API на нашем домене; клиент обращается только к нему (без fallback).

## Последствия

- Новый серверный компонент (сервис аккаунтов + база) — отдельное развёртывание, мониторинг и резервные копии (`docs/SERVER_DEPLOYMENT.md`).
- Почтовая отправка — внешний сервис или свой SMTP; Telegram — бот FuntiDesk через Telegram Bot API (`api.telegram.org`). Обе — новые внешние зависимости, принятые решением владельца 2026-10-13; при их недоступности вход этим способом не работает (fail closed), второй способ и всё остальное в FuntiDesk работают. Токен бота и ключи почты — только на сервере, не в репозитории.
- Клиент: экран входа, «Мои устройства» из кабинета, синхронизация семьи; `is_disable_account()` перестаёт быть `true` только для нашего сервиса (upstream-аккаунт остаётся выключенным).
- Объём — несколько этапов; первым предлагается (а)+(д).

## Порядок (предложение)

1. Решение владельца по пунктам «Что нужно решить».
2. ADR дополняется выбранным и становится «принято».
3. Этап 1: сервис аккаунтов, вход через Telegram и почту, список устройств в клиенте. Этап 2: синхронизация семьи, удалённое удаление. Этап 3 (если нужно): страница в браузере, журнал.
