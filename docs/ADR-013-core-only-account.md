# ADR-013: кабинет на одном Core без witness

Статус: принято владельцем 2026-10-17. Заменяет ADR-011 и требование witness в ADR-012.

## Решение

Кабинет хранит своё состояние в основной SQLite-базе на Core (`desk.funti.cc`). Операция подтверждается после успешной SQLite-транзакции. Ни DE, ни отдельный сервер подтверждений, ни relay для него не требуются. В Compose кабинета остаются только API и SMTP; используются уже действующие Caddy и hbbs resolver.

Удаляются код witness/recovery/relay, соответствующие CLI-команды, конфигурация, сети и обязательные переменные окружения. Это основной режим работы, без переключателя или сетевого fallback. Сохраняются WAL, SQLite-транзакции, блокировка второго процесса, ограничения запросов, HttpOnly/CSRF, подписи устройств, журнал удалений и ACK. Вход в аккаунт по-прежнему не даёт доступа к экрану компьютера.

## Обновление существующей базы

Схема v4 транзакционно удаляет только таблицу `recovery_state` и её служебные триггеры. Аккаунты, действующие и отозванные сессии, устройства, семья, события, ACK, избранное и история сохраняются. Обновление не восстанавливает старую базу и не возвращает отметку независимого сервера: основной источник истины — нынешняя база Core, включая уже записанные изменения. Ключ аккаунта и идентичности компьютеров сохраняются.

Перед обновлением делается закрытая согласованная SQLite-копия. Миграция проверяется на этой копии сравнением прикладных таблиц и `integrity_check`. После запуска v4 старый бинарный файл v3 не используется для отката. Отдельные службы резервного копирования или новая инфраструктура этим решением не вводятся.

## Эксплуатация

Обычное восстановление выполняется из выбранной согласованной SQLite-копии при остановленном API. Вместе с базой сохраняется существующий account key. Старые копии содержат старое состояние: независимой гарантии от возврата ранее удалённых записей больше нет. Это принятое упрощение архитектуры по прямому решению владельца, а не скрытое отключение проверки при сбое.

DE не участвует в обслуживании FuntiDesk. Уже сохранённый на DE архив не запускается и не используется как рабочая зависимость. Новые сервисы добавляются только под конкретную задачу.
