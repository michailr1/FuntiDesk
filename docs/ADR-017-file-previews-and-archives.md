# ADR-017: миниатюры фото и передача множества мелких файлов

Статус: миниатюры приняты к реализации. Изменения протокола, удалённой стороны и интерфейса поставляются согласованно. Режим мелких файлов требует отдельного технического решения.

## Задача

1. **Миниатюры.** В окне передачи файлов видеть фото удалённого компьютера, не скачивая их по одному.
2. **Мелкие файлы.** Папка с тысячами маленьких файлов (фото с телефона, проект, архив почты) передаётся медленно: на каждый файл уходит свой обмен сообщениями. Нужно передавать такие папки быстрее.

Сейчас в протоколе передачи файлов (`FileAction` в `libs/base/protos/message.proto`) есть только чтение папки, передача по одному файлу блоками (уже сжатыми zstd), создание, удаление и переименование. Ни миниатюр, ни передачи папки одним потоком нет. Обе задачи без изменения протокола решаются только частично (ниже).

## Миниатюры

**Вариант А — без изменения протокола.** Клиент сам скачивает изображения открытой папки во временный кэш и показывает уменьшенными. Подходит только для маленьких файлов: папка из 200 фото по 4 МБ — это 800 МБ трафика ради предпросмотра. Отклоняется.

**Вариант Б — новое действие протокола (принят 2026-11-03).**

- Новое `FileAction.funti_read_thumbnail { id, path, max_side }` и ответ `FileResponse.funti_thumbnail { id, path, jpeg | error }`, номера полей с 1001, чтобы не пересечься с будущими полями upstream.
- Удалённый компьютер в процессе пользователя (там же, где сейчас читаются папки) декодирует файл через уже подключённый `image 0.24`, уменьшает до 160 px по длинной стороне и отвечает JPEG до 32 КБ.
- Форматы: JPEG, PNG, GIF (первый кадр), BMP, WebP. HEIC и видео не поддерживаются: значок файла остаётся.
- Ограничения на удалённой стороне: файл до 50 МБ, картинка до 40 Мп (проверяется по заголовку до декодирования), ответ до 32 КБ. Запросы обрабатываются по одному, как другие операции с файлами; окно держит не больше двух запросов сразу и только для видимых строк. Поворот по EXIF, прозрачное — на белом. Фото 24 Мп — 0,4 с.
- Права: только когда разрешена передача файлов. Миниатюра — меньше, чем уже даёт обычное скачивание, нового доступа нет.
- Клиент: кнопка «Миниатюры / Обычный список» на каждой панели (запоминается), запрос только для видимых строк, кэш в памяти до 1000 миниатюр до закрытия окна, на диск не пишется. Свои фото окно декодирует само, без протокола.
- Совместимость: старые версии FuntiDesk игнорируют неизвестное поле (проверено разбором). Версия собеседника у всех сборок одна (1.5.0), поэтому окно определяет это по трём ответам подряд, не пришедшим за 10 с: сообщает «обновите FuntiDesk» и больше не спрашивает.

## Множество мелких файлов

**Сначала измерить.** До кода — замер на двух реальных компьютерах: папка из 5 000 файлов по 20 КБ (100 МБ) против одного файла 100 МБ, P2P и через hbbr. Если разница меньше двух раз, задача снимается.

**Вариант А — без изменения протокола.** Пункт меню «Сжать в ZIP» и «Распаковать» работает только на панели «Это устройство»: отправляет и принимает один архив, а распаковать его на удалённом компьютере придётся вручную. Удобно только в одну сторону. Может быть временной мерой, если замер покажет проблему, а вариант Б отложат.

**Вариант Б — передача папки одним потоком (предлагается, если замер подтвердит).**

- Новый режим передачи папки: отправляющая сторона пишет содержимое как поток tar прямо в блоки текущей передачи (zstd уже есть), принимающая сразу распаковывает. Временные архивы на диске не создаются.
- Включается сам для папок, где больше 200 файлов и средний размер меньше 256 КБ. В остальных случаях работает обычная передача.
- Безопасность распаковки обязательна: только относительные пути внутри папки назначения, без `..`, абсолютных путей и ссылок; без устройств и прав доступа из архива; не больше объявленного размера и числа файлов. Иначе передача останавливается с ошибкой, без частичной перезаписи чужих файлов.
- Совпадающие имена решаются один раз на всю папку («Оставить оба / Заменить / Пропустить», как уже сделано для обычной передачи).
- Новых зависимостей нет: tar пишется вручную (формат ustar простой) либо через `zip 0.6`, который уже есть. Выбор — при реализации, по размеру кода.

## Последствия

- Изменяется протокол: правка `message.proto`, обработка в `server/connection.rs` и `ui_cm_interface.rs`, клиентская часть во Flutter. По правилу 2 `AGENTS.md` это допустимо только потому, что без протокола задача не решается приемлемо; изменения добавочные, старые сообщения не меняются.
- Оба варианта Б — отдельные PR, каждый с проверкой на двух компьютерах: миниатюры — папка из 500 фото и битые файлы; поток — 5 000 файлов, имена с `..` и ссылками в подготовленном злонамеренном потоке, обрыв на середине.
- Браузерная консоль (ADR-014/015) не меняется до отдельного решения.

## Решение:1. Миниатюры: вариант Б — **да** (2026-11-03).
2. Мелкие файлы — ещё нужно выбрать: сначала замер, затем по результату вариант Б — да или нет; нужен ли до этого временный вариант А.
