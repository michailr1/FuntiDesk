# ADR-002: доверие к механизму custom client

Статус: принято

Дата: 2026-09-17

## Контекст

Upstream-клиент содержит механизм `read_custom_client()`, который принимает внешнюю конфигурацию после проверки подписи публичным ключом, не принадлежащим FuntiDesk. Через этот канал могут задаваться имя приложения и наборы настроек.

Для FuntiDesk это нарушает модель доверия: production-бинарь не должен принимать управляющую конфигурацию, доверие к которой находится вне нашего контроля.

## Решение

На первом этапе FuntiDesk **отключает механизм custom client полностью** в production-сборках.

Мы не заменяем upstream-ключ своим до появления реальной продуктовой необходимости в удалённо подписываемой конфигурации.

Причины:

- меньшая поверхность доверия;
- проще доказать fail closed;
- для сценария владельца, семьи и друзей динамический custom-client канал сейчас не нужен;
- собственный ключ добавил бы отдельный жизненный цикл секретов и процедуру ротации без текущей пользы.

## Требования реализации

- production-клиент не должен читать или применять `custom.txt` и эквивалентный внешний custom-client payload;
- отсутствие этого файла не должно менять поведение клиента;
- наличие специально сформированного файла не должно менять `app-name`, инфраструктурные endpoints или policy settings;
- тест этого свойства входит в security acceptance Windows MVP.

## Будущее

Если появится необходимость централизованно раздавать подписанную конфигурацию, механизм проектируется отдельно с нашим ключом, версионированием, ротацией и rollback policy. Возврат upstream trust key запрещён.
