# FuntiDesk — утверждённый дизайн Windows (концепция v0.1)

**Статус:** визуальная концепция окна управления принята пользователем 2026-09-30. Это дизайн-спецификация для будущей реализации во Flutter; **не** свидетельство того, что соответствующие функции уже реализованы в клиенте.

## 1. Главный экран Windows

- Собственная визуальная идентичность FuntiDesk, не копировать исходный интерфейс RustDesk. Светлый современный интерфейс, компактная навигация и преимущественно синие акценты.
- Главный приоритет — быстрое подключение и избранные/доступные устройства; не расходовать половину рабочего пространства на иллюстрацию.
- Иллюстрация бренда: человек и **Фунтик**, стилизованный (анимированный, но узнаваемый по реальным фотографиям): компактный серебристо-серо-бежевый полосатый кот, округлая мордочка, зелёные глаза, прямые уши, характерное серьёзное выражение и полосатый хвост. Небольшой элемент, не доминирующий над устройствами и формой подключения.
- Карточка собственного устройства: отображаемый ID с копированием, временный пароль с показом/обновлением, доступность.
- Карточки устройств и история; отдельное обозначение платформы и поддерживаемых возможностей.
- Для iOS **при трансляции самого iPhone**: только просмотр экрана другого участника, без удалённых нажатий и системного управления устройством. iOS-клиент при этом может управлять поддерживаемыми удалёнными компьютерами.
- **P2P/Relay не показывать как гарантированные постоянные свойства офлайн-устройства:** фактический транспорт определяется только после установления конкретного сеанса; для неактивного устройства показать «Не подключено» или скрыть транспорт.

## 2. Утверждённое окно активного удалённого сеанса Windows

Основной референс — визуальный макет окна управления, утверждённый в UI-чате 2026-09-30 (19:26 MSK). При переносе в код считать изображение концептуальным макетом, не буквальным скриншотом работающей реализации.

### Верхняя строка сеанса — компактная, всегда видимая

- FuntiDesk, имя удалённого ПК и его ID, ОС и индикатор доступности.
- **Явная метка фактически активного транспорта: «P2P» (зелёная) / «Relay» (янтарная).** Это взаимоисключающие статусы активного сеанса; при согласовании соединения «Подключение…», при переподключении «Переподключение…». Не показывать две одновременно как два установленных транспорта; при будущем бесшовном переключении показывать проверенный текущий канал и статус перехода.
- Рядом: режим доступа — «Полный доступ» или «Только просмотр» — и текущая задержка (мс).
- Кнопки стандартного окна и понятное завершение подключения.

### Панель управления

- Рядом с поверхностью удалённого экрана: клавиатура, буфер обмена, файлы, параметры изображения/экрана, качество, запись, «Отключиться».
- Большую часть площади занимает **сам удалённый экран**; панель можно скрывать в компактный режим.
- Правая панель **опциональная/сворачиваемая**, не отнимает постоянное пространство на маленьком экране; сведения о сеансе, транспорт, задержка, качество, состояние шифрования, режим доступа.
- Отдельно показывать ограничения конкретной удалённой ОС, например при подключении к транслирующему экран iPhone — «Только просмотр»; не предлагать недоступные действия.

### Нижняя компактная строка

- Имя ПК и разрешение удалённого экрана; по доступности и с корректным источником: показатели нагрузки CPU/RAM (если удалённый клиент их предоставляет), фактические скорости входящего/исходящего трафика и прочая диагностика.
- Не показывать вымышленные CPU/RAM/скорость/«TLS» или другие значения: до реализации телеметрии скрыть или обозначать отсутствие данных, а алгоритм шифрования маркировать согласно фактическому протоколу и проверенной сессии.

## 3. Правила реализации

- Flutter/Dart для нового UI, существующее сетевое ядро Rust сохранить, связь через Flutter Rust Bridge; надписи на русском.
- Информация о транспорте и режиме доступа должна идти от **реального состояния соединения**, а не вычисляться по сетевому типу устройства или предполагаться по умолчанию. Определить контракт Rust → Flutter (enum transport: connecting/direct_p2p/relay/reconnecting/disconnected; capabilities: view/control/file_transfer/clipboard; rtt, throughput и т.д.) до отрисовки метрик.
- Никаких обещаний полного управления iPhone: стандартные приложения iOS не имеют соответствующих системных прав.
- Дизайн не должен мешать текущей разработке NAT refresh (MIK-16) и будущему relay→P2P handover (MIK-23). UI может позднее отображать смену транспорта без разрыва активного сеанса, когда backend реализует это.
- Адаптивная компоновка для небольших окон и HiDPI; светлая тема сначала, тёмная позже.
- Никаких паролей или рабочих идентификаторов на реальных публичных маркетинговых скриншотах: заменять демонстрационными данными.

## 4. Приёмка UI-концепции

1. На экране подключения видны собственный ID, пароль, поле подключения, доступные устройства и небольшой узнаваемый персонаж Фунтик.
2. Активная сессия: сразу видно **P2P или Relay**, RTT и **Полный доступ или Только просмотр**; статусы честно следуют реальному состоянию.
3. Трансляция экрана iOS отображается только как «Только просмотр»; управление iPhone не показывать.
4. В полноэкранном режиме не теряется рабочая площадь: панель компактная/автоскрываемая, дополнительная диагностика сворачивается.
5. Ухудшение сети/переход Relay↔P2P в будущем меняет UI только при подтверждённой смене транспорта.
