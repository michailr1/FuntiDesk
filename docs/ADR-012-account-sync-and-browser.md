# ADR-012: синхронизация списков и браузерное подключение

Дата: 2026-10-15. Продуктовые требования приняты владельцем: веб-клиент по временному и постоянному паролю, синхронизация избранного и истории. Техническое решение ниже реализуется в draft PR #50; рабочая приёмка и публикация ещё не выполнены.

## Разделение доступа

Почтовая сессия разрешает чтение и изменение списков одного аккаунта. Она не является учётными данными удалённого сеанса. Пароль компьютера проверяет принимающий клиент по существующему протоколу; действуют его ограничения и запрос подтверждения, если он включён. Избранное, история и копия семьи не становятся источником доверия.

## Синхронизация

Отдельные таблицы схемы v3 и API `/library`, `/library/favorites`, `/library/history`, `/library/history/clear`. Для избранного используется сравнение версии всего ограниченного списка; при конфликте `409` клиент перечитывает список, но не отправляет старый список заново. Максимум 128 записей с ID и названием, без локальных настроек или секретов.

История — сообщённые клиентом успешные исходящие подключения удалённого экрана, не независимый серверный аудит. Запись содержит случайный идентификатор события, исходное устройство аккаунта, ID/название назначения и время. Повтор одного события идемпотентен. При очистке увеличивается поколение истории; старые отложенные события не принимаются. Браузер может читать и очищать историю; запись событий от нативного клиента проверяет принадлежность исходного устройства аккаунту. Браузерные сеансы потребуют собственного проверяемого источника событий и не должны выдавать себя за нативное устройство.

Для первого варианта устанавливаются ограничения: до 1000 событий аккаунта за последние 90 дней; до 120 изменений в минуту на аккаунт, тело до существующих 64 КиБ. По решению владельца 2026-10-17 изменения подтверждаются SQLite-транзакцией на Core, без witness и DE: [ADR-013](ADR-013-core-only-account.md). Схема v4 сохраняет списки и поколения истории; откат исполняемого файла требует совместимости со схемой.

Уточнение владельца 2026-10-15: синхронизация автоматически действует на всех поддерживаемых устройствах, где выполнен вход в аккаунт, без отдельного переключателя. На Windows это относится к новому и уже сохранённому входу; прежний opt-in больше не учитывается. Существующее локальное избранное можно перенести отдельной командой; старые локальные недавние записи не импортируются. Без входа работает прежнее локальное избранное. При выходе удаляются активные списки аккаунта; очереди и операции привязаны к точному аккаунту и поколению истории. Native actor обновляет списки в существующем минутном цикле; видимый веб-кабинет перечитывает их каждые 30 секунд и при возврате на вкладку. Это фоновая синхронизация, без гарантии мгновенного push-обновления.

## Браузерный транспорт

Собственный небольшой интерфейс на `/connect/`, без копирования upstream UI или закрытого браузерного ядра. Используются текущие открытые protobuf-описания, поставляемые локально зависимости для protobuf и криптографии, WebCodecs VP9 в настольном Chromium. Нет CDN, внешнего API, хранения паролей и токенов сеанса в URL или браузерном постоянном хранилище.

Сигнализация и relay идут только на закреплённые WSS-маршруты собственного домена. Ключ собственного hbbs закреплён в сборке; полученная подпись ID/ключа и подписанная идентичность принимающего клиента проверяются до отправки пароля. При отсутствии/несовпадении ключа соединение закрывается без незашифрованного пути. Сессионный ключ шифруется для проверенного box-ключа компьютера; дальнейший обмен использует существующее сквозное шифрование протокола. HTTPS/WSS не заменяет его.

Первый этап: экран, мышь, клавиатура, прекращение сеанса. Ни семейная браузерная идентичность, ни файлы, звук или буфер обмена не включаются автоматически. Публикация WSS требует отдельного воспроизводимого патча Caddy/Compose и проверки настоящего Windows-сеанса; наличие интерфейса и протокольные тесты не закрывают эту приёмку.
