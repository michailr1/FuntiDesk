# ADR-020: журнал подключений на компьютере

Статус: **принят владельцем 2026-11-11** («имена файлов делаем»); предложен архитектором 2026-11-11, по решению владельца 2026-11-09 («журнал подключений») и порядку от 2026-11-11 (журнал → Wake-on-LAN → администрирование → указка). Этап 1 реализован в том же PR; этап 2 — отдельный PR.

## Задача

Владелец компьютера должен видеть, кто и когда к нему подключался, сколько длился сеанс, передавались ли файлы и какие попытки были отклонены. Сейчас этого нигде нет: RustDesk отправляет такие записи на свой платный сервер, у FuntiDesk его нет (R-14, адрес пустой), и записи просто отбрасываются.

## Решение

Журнал ведётся **только на самом компьютере**, в файле рядом с настройками процесса, который принимает подключения. Он никуда не отправляется: ни на сервер, ни в кабинет, ни другим членам семьи.

- **Источник событий** — те же три места, где upstream готовит записи аудита (`post_conn_audit`, `post_file_audit`, `post_alarm_audit` в `server/connection.rs`). В каждом одна строка вызова `funti_journal`; протокол и ядро не меняются.
- **Что пишется:**
  - `connected` — время, ID и имя подключившегося, IP, вид сеанса (экран, файлы, порт, камера, терминал), способ входа;
  - `closed` — время и длительность;
  - `files` — направление, число файлов и общий размер, папка на этом компьютере и имена десяти самых больших файлов (решение владельца 2026-11-11);
  - `refused` — отклонённая попытка: причина, IP, ID и имя, если известны.
- **Что не пишется:** содержимое файлов и сеанса, буфер обмена, пароли и коды. Первое обращение до авторизации (`action: new`) не пишется: его может вызвать кто угодно, и оно засоряло бы журнал.
- **Формат** — JSON, одно событие в строке: `funti-journal.jsonl`. Имя и ID присылает другая сторона, поэтому они обрезаются до 64 символов, имена файлов и папка — до 200; управляющие символы удаляются.
- **Размер** — не больше 1 МБ на файл (несколько тысяч событий). Заполненный файл становится `funti-journal.1.jsonl`, прежний такой файл удаляется: всего не больше 2 МБ, без фоновых задач.
- **Ошибка записи** не мешает подключению: она попадает в обычный лог.
- На Unix файл создаётся с правами `0600`. На Windows он лежит в каталоге настроек службы, как остальные её файлы.

## Чего это не закрывает

- Тот, у кого есть права администратора на компьютере, может журнал стереть или изменить. Это журнал для владельца, не доказательство для третьих лиц.
- Подключения, которые этот компьютер сам делал к другим, сюда не попадают: они есть в «Недавних».

## Этапы

1. **Запись** (этот PR): модуль `client/src/funti_journal.rs`, хранилище `funti_journal/store.rs` с тестами (`scripts/ci/test-funti-journal.sh`), три вызова в `connection.rs`.
2. **Просмотр**: страница «Журнал» в настройках. Служба отдаёт последние события окну по существующему IPC (одно новое сообщение), окно показывает список: кто, когда, сколько, файлы, отклонённые попытки. Кнопка «Очистить» — с подтверждением.
3. По решению владельца, позже: уведомление о подключении в отсутствие владельца; журнал в кабинете — только отдельным ADR, потому что это уже отправка данных с компьютера.

## Отвергнутые варианты

- **SQLite на клиенте** — новая зависимость ради списка из нескольких тысяч строк.
- **Отправка в кабинет** — журнал с IP и именами уходил бы с компьютера; для семейного сервиса это лишний риск без запроса владельца.
- **Журнал Windows (Event Log)** — только Windows, и обычному человеку его не открыть.
