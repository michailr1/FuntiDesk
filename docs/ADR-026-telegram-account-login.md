# ADR-026: вход в аккаунт через Telegram

## Решение

Telegram дополняет вход по коду из письма. Новый пользователь может создать аккаунт без почты; существующий пользователь привязывает Telegram из уже открытого кабинета. Два аккаунта автоматически не объединяются. Это заменяет прежнее исключение Telegram в ADR-009, сохраняя почтовый вход и права устройств.

Сайт создаёт случайный одноразовый код на пять минут. Пользователь отправляет его существующему боту и явно подтверждает вход. Бот передаёт код и числовой Telegram ID через отдельный защищённый server-to-server endpoint. Браузер опрашивает состояние и однократно получает прежнюю HttpOnly-сессию. Никаких ключей бота, доверенных Telegram ID или bearer-токенов в браузере нет.

## Границы и хранение

- Существующие Host/Origin/CSRF-проверки сохраняются. Чужая вкладка без cookie исходного браузера не может опросить или погасить запрос. Привязка дополнительно связана с исходной активной сессией аккаунта.
- Bridge принимает только отдельный 256-битный ключ, не браузерные cookie и не native-авторизацию. Бот берёт ID только из доверенного private update; подтверждение связано с отправителем.
- Коды имеют 40 бит случайности; в SQLite сохраняются только HMAC кода, контекста и Telegram ID. Ограничены создание, подтверждения, срок жизни и число активных запросов. Пользователь не должен передавать код другим людям.
- Схема 6 допускает NULL email; добавляет таблицы идентичностей и краткоживущих запросов. Старые ID аккаунтов, почта, устройства, семейные списки, события и сессии сохраняются. Фиктивные адреса не создаются. Старые клиенты продолжают почтовый вход.
- Telegram уникален для одного аккаунта. Конфликт не раскрывает чужой аккаунт. Отключение разрешено при наличии почты и отзывает все сессии. Нельзя удалить единственный способ входа.
- Запросы действуют пять минут и удаляются ежеминутным обслуживанием после истечения срока; связь с Telegram сохраняется до отключения. Имя, телефон и username не запрашиваются и не сохраняются.

## Отказ и поставка

Без ключа функция выключена; почтовый вход работает независимо. Недоступность бота не влияет на существующие сеансы удалённого доступа. Подтверждение в Telegram не даёт права управлять компьютером: нужны его пароль или локальные права семьи.

Перед обновлением нужна проверенная копия SQLite и проверка миграции на копии. До включения проверяются негативные HTTP-сценарии, истечение, повторное погашение, конфликт привязки, миграция и почтовый вход. Откат на сервер схемы 5 требует остановки API и восстановления согласованной копии; новые записи после обновления нельзя молча потерять. Аккаунт и бот поставляются согласованно; ключ не хранится в Git или аргументах команд.
