# Подпись релизов: инструкция владельца

Зачем: сейчас клиент доверяет обновлению, если оно лежит в релизе на GitHub. Если кто-то получит доступ к GitHub-аккаунту, он сможет разослать всем поддельное обновление. С подписью клиент ставит только то, что подписано вашим ключом, а ключ есть только на вашем компьютере. Решение — [ADR-018](ADR-018-release-signing.md) (PR #112).

**Состояние: подпись отложена решением владельца 2026-11-11** («пока оставим без ключа, на GitHub стоит двухфакторка»). Релизы выходят по прежнему порядку, подписывать ничего не нужно. Ключ уже создан (шаги 1–2 выполнены), публичная часть записана в ADR-018. Эта инструкция — на случай, когда подпись решим включить: тогда понадобятся шаги 3–5.

Все команды — в PowerShell на вашем компьютере с Windows 10/11.

## Шаг 1. Создать ключ (один раз)

```powershell
mkdir $env:USERPROFILE\.ssh -Force
ssh-keygen -t ed25519 -C funtidesk-release -f $env:USERPROFILE\.ssh\funtidesk-release
```

Команда дважды спросит пароль ключа. Придумайте его и сохраните в менеджере паролей: он нужен при каждой подписи, восстановить его нельзя.

Появятся два файла в `C:\Users\<вы>\.ssh\`:

| Файл | Что это | Кому можно дать |
|---|---|---|
| `funtidesk-release` | приватный ключ | **никому**: ни Claude, ни Codex, ни в GitHub, ни в чат |
| `funtidesk-release.pub` | публичный ключ | всем, это не секрет |

## Шаг 2. Переслать публичный ключ

```powershell
Get-Content $env:USERPROFILE\.ssh\funtidesk-release.pub
```

Выведется одна строка вида `ssh-ed25519 AAAAC3Nza... funtidesk-release`. Скопируйте её целиком и вставьте в чат с Claude (или в комментарий к PR #112). Проверьте, что строка начинается с `ssh-ed25519` и что это файл с `.pub`.

После этого архитектор добавит ключ в клиент, в `install.ps1` и в `infra/release/allowed_signers`, и подпись станет обязательной со следующего релиза.

## Шаг 3. Резервная копия приватного ключа

Скопируйте файл `funtidesk-release` (без `.pub`) на флешку или в менеджер паролей и уберите в надёжное место. Не кладите его в облачную папку и в почту.

Если ключ потерять, уже установленные клиенты не примут обновления, подписанные новым ключом: каждому придётся один раз переустановить FuntiDesk вручную.

## Шаг 4. GitHub CLI (один раз)

Нужен, чтобы скрипт сам приложил подпись к релизу.

```powershell
winget install GitHub.cli
gh auth login
```

В `gh auth login` выбрать: GitHub.com → HTTPS → Login with a web browser. Без GitHub CLI подписать тоже можно, но файл подписи придётся приложить к релизу в браузере (скрипт скажет, какой).

## Шаг 5. Подписать релиз Windows (каждый раз)

Архитектор собирает релиз и сообщает его тег, например `funtidesk-windows-1a2b3c4`. Релиз в этот момент ещё не «последний», клиенты его не видят.

```powershell
gh api repos/michailr1/FuntiDesk/contents/scripts/release/sign-release.ps1 -H "Accept: application/vnd.github.raw" > $env:USERPROFILE\sign-release.ps1
powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\sign-release.ps1 funtidesk-windows-1a2b3c4
```

Что делает скрипт:

1. Скачивает `SHA256SUMS.txt` релиза и показывает его: имена файлов и их контрольные суммы.
2. Спрашивает `Sign? (y/n)`. Сверьте суммы с теми, что архитектор прислал вместе с тегом. Совпадают — `y`.
3. Спрашивает пароль ключа (его запрашивает `ssh-keygen`, пароль никуда не передаётся).
4. Подписывает, сам проверяет подпись, прикладывает `SHA256SUMS.txt.sig` к релизу.
5. Запускает на GitHub проверку `Release promote`: она ещё раз проверяет подпись и суммы всех файлов и только тогда делает релиз «последним».

Если что-то не сходится, скрипт останавливается с ошибкой, и релиз остаётся невидимым для клиентов. Пришлите текст ошибки архитектору.

## Если ключ украден или есть подозрение

Сразу сообщите архитектору. Порядок: новый ключ (шаги 1–3), релиз с новым ключом в списке, подписанный ещё старым ключом, затем старый ключ убирается из списка.

## Чего не делать

- Не отправлять файл `funtidesk-release` (без `.pub`) никому и никуда.
- Не подписывать релиз, если суммы на экране не совпадают с присланными.
- Не хранить пароль ключа в том же месте, что и сам ключ.
