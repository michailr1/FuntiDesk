# Браузерный клиент FuntiDesk

Собственный интерфейс и транспорт для текущих открытых protobuf-описаний в `client/`: WebCodecs VP9 → Windows, удалённый экран, мышь и клавиатура. По [ADR-014](../docs/ADR-014-phone-web-console.md), #65 подготовлен интерфейс сеанса для телефона; приёмка в Safari на iPhone и с экрана «Домой» ещё впереди. Веб-клиент не наследует семейное доверие из кабинета; временный или постоянный пароль проверяет принимающий FuntiDesk. Требуется клиент с обменом ключами v1; незашифрованного пути нет.

## Воспроизводимая сборка

Node 22 или новее:

```sh
npm ci --prefix web-client --ignore-scripts
npm --prefix web-client run build
npm --prefix web-client test
python3 scripts/web/package.py --write-manifest
python3 scripts/web/package.py --output /tmp/funtidesk-web.tar
```

`build.mjs` генерирует статические protobuf-кодеки из исходных `.proto`, затем собирает `web/connect/session.js` и уведомления о лицензиях. В браузере не используются генерация кода через `eval`, CDN или динамическая загрузка зависимостей. `wasm-unsafe-eval` нужен криптографической библиотеке, а `unsafe-eval` для JavaScript не разрешён. Сгенерированные публичные файлы включены в Git и проверяются повторной сборкой; промежуточные исходники и `node_modules` игнорируются.

Описания протокола — AGPL-3.0, исходные уведомления RustDesk/Purslane сохранены в `client/`. Криптографические и protobuf-зависимости закреплены в `package-lock.json`, их полные лицензии поставляются в `web/connect/licenses.html`. Исторический webclient-v1 изучен как справочный код; его небезопасный транспорт и UI не импортированы.

## Развёртывание и приёмка

Техническое решение: [ADR-012](../docs/ADR-012-account-sync-and-browser.md). Отдельный WSS-фрагмент — `infra/funtidesk-account/Caddyfile.web-client.fragment`, дополнительная сеть Caddy — `caddy-web-client.override.yaml`. Для живой приёмки подготовлен отдельный `scripts/account/update-browser-desk.py`: он сохраняет текущие API и страницы кабинета, проверяет оба manifest, изменяет только desk-блок и добавляет только сеть серверов. При неуспешной готовности возвращает прежние Caddyfile, webroot и сети. При последующих recreate сохранять оба overlay из закрытого integration-каталога и остальные сайты. Это кандидат для проверки Windows, а не принятый релиз.

Проверки криптографии сопоставляют побайтовые контрольные значения текущего нативного Rust-клиента: подписи обеих идентичностей, ID, запечатанный ключ, отдельные ключи направлений и парольный challenge. Протокольный тест с синтетическим компьютером не заменяет реальную Windows-приёмку: временный пароль, постоянный пароль, отказ пароля/ключа, запрет ввода, отзыв подтверждения, обрыв сети и существующие native-native подключения.

На телефоне (`pointer: coarse`) после входа остаются экран и перетаскиваемое меню: тачпад/касание, масштаб, системная клавиатура и спецклавиши из меню, монитор, качество, подтверждение Ctrl+Alt+Del, завершение. При увеличении в режиме тачпада экран следует за курсором: точка управления остаётся в центре доступной области, у краёв рабочего стола прокрутка останавливается. После ручного перемещения двумя пальцами следующее движение курсора возобновляет слежение; прямое касание не сдвигает экран. Wake Lock запрашивается только во время сеанса; отказ не обрывает подключение. Подсказка — собственный слой с кнопкой «Понятно»: один раз за открытие страницы и из меню, без записи в хранилище браузера. `/connect/app.webmanifest` открывает страницу в `standalone`, без service worker и кеширования паролей/сеансов. Для manifest нужен согласованный `manifest-src 'self'` в существующем desk-блоке Caddy; порядок — в [ACCOUNT_DEPLOYMENT.md](../docs/ACCOUNT_DEPLOYMENT.md).

Значок iOS `/connect/apple-touch-icon.png` (180×180, `apple-touch-icon`) растеризован из `design/brand/funtidesk-mark.svg` существующим Skia-renderer Android. Повторный экспорт из корня в окружении с `skia-python` и `numpy`:

```python
import numpy as np
import skia
from scripts.brand.export_android_icons import render
image = skia.Image.fromarray(np.ascontiguousarray(render(180, 180)),
    colorType=skia.kRGBA_8888_ColorType, alphaType=skia.kUnpremul_AlphaType)
image.save('web/connect/apple-touch-icon.png', skia.kPNG)
```

Пока не включены: семейный вход из браузера, звук, буфер обмена, камера и автоматическая запись браузерных сеансов в историю аккаунта. Некоторые сочетания перехватывает браузер. Chromium с эмуляцией касаний проверяет транспорт, жесты, клавиши, поворот и режим просмотра; он не заменяет реальный iPhone, диктовку и клавиатуру Safari.

На телефоне видимый указатель точки управления рисуется поверх видео: следует за жестами и входящими `cursor_position`, учитывает масштаб и смещение экрана. Это постоянная контрастная стрелка, не передача формы системного курсора. В режиме только просмотра указатель управления скрыт. При обычном вводе используется только системная клавиатура; спецклавиши раскрываются отдельно в меню, поле ввода видно; экран подстраивается под доступную область над системной клавиатурой и панелью. Проверки Chromium включают контраст подписей, положение указателя, composition/Enter и изменение visual viewport. Автозаполнение отключено стандартными атрибутами; поведение подсказок и диктовки iOS проверяется на самом iPhone.

## Короткое восстановление телефонного сеанса

После первого разрешённого входа телефонная вкладка держит производное от пароля только в RAM. После сворачивания/обрыва допускается одна автоматическая попытка в течение пяти минут, с проверкой того же ID/ключа/соли, новым challenge, ключами шифрования и актуальными правами компьютера. Обычный desktop-путь не использует этот кеш. «Завершить», истечение срока и отказ/смена учётных данных очищают его. При pagehide RAM очищается; принятое исключение для reload описано ниже. Зависшие таймеры iOS не продлевают срок: он проверяется перед использованием. Перезагруженная вкладка восстановиться из RAM не может: по следующему уточнению владельца принята одноразовая запись `sessionStorage` на пять минут, создаваемая только при уходе подтверждённого сеанса. При reload запись удаляется до попытки входа. Обычный переход, другой ID, незавершённое восстановление и desktop автоматического входа не дают. Если iOS не вызвала pagehide или хранилище запрещено, остаётся обычный вход. Если временный пароль уже изменился на компьютере, нужен новый пароль; таймауты/правила Windows-клиента не меняются.

Форма содержит стандартные `username`/`current-password` атрибуты для Safari/Apple «Пароли». Системным сохранением и подтверждением управляет пользователь; обычно оно подходит для постоянного пароля. FuntiDesk не пишет секрет в localStorage, cookie, URL или аккаунт. Исключение sessionStorage для reload содержит производное, эквивалентное паролю для данной соли: оно доступно коду того же origin; клиентские пять минут не отзывают украденный секрет на сервере. Формат/ограничения и принятое решение — в разделе reload ADR-014. Уточнение принято архитектором 2026-10-18 (#76, #78). #76 выложен на desk из main `5ba366985db8` ([проверка поставки](../docs/reviews/2026-10-18-phone-web-deploy.md)); #77/#78 выложены вместе из main `6277d1b4431a`. Расширение хранения требует нового ADR. Реальное сворачивание, блокировка и системное автозаполнение проверяются на iPhone; Chromium этого не заменяет.

При отсутствии Navigation Timing 2 тип обновления проверяется по legacy `performance.navigation.type`. Обычный переход и Back/Forward не становятся reload, неизвестный тип не разрешает автовход. Если запись отсутствует, повреждена, просрочена или хранилище недоступно, форма показывает причину без ID/ключей/производного пароля; возврат страницы из BFCache остаётся без автовхода по ADR-014, с явным сообщением. Эти сообщения помогают проверке реального iPhone; тесты WebKit на Linux её не заменяют.

Сообщение об отсутствующих данных показывается только по несекретной метке времени предыдущего подтверждённого сеанса (`funtidesk.phone-reload.attempt`). Без неё обновление пустой формы остаётся обычной формой. Сообщение при BFCache показывается только если страница помнит активный сеанс перед pagehide; признак хранится только в RAM. Метка не участвует в авторизации и очищается вместе с записью.

## Файлы (#67, ADR-015)
Кнопка «Файлы» в форме сеанса и меню телефона открывает отдельный файловый вход (пароль компьютера/системное автозаполнение). Вход в кабинет не участвует; постоянное хранение секретов не расширено. Один файл до 50 МБ, без замены существующего имени, папок целиком и докачки; прогресс, отмена и сохранение готового файла через Safari/браузер. Закрытие панели/основного сеанса очищает соединение и Blob URL. Запрет файлов на компьютере скрывает кнопку. `fzstd@0.1.1` включён в bundle/notices для штатного сжатия 128-KiB блоков. `npm test` проверяет блоки/очередь, `npm run test:files` — отдельный шифрованный handshake, UI, download/upload/отмену/права. Нужна настоящая приёмка Windows + iPhone, особенно сохранение в «Файлы» и ограничения фонового Safari.

Панель файлов на телефоне занимает доступный экран: прокручивается список, навигация и отправка остаются на месте. Папки/диски всегда выше файлов; по умолчанию естественная сортировка А–Я (`Folder2` перед `Folder10`), доступны обратное имя, размер и дата. Поиск ограничен текущей папкой и не отправляется на сервер. Переход по цепочке пути/кнопкой «Выше», ручной путь и переименование скрыты до запроса. «Отправить файл» открывает системный выбор; имя/подтверждение появляются после выбора. Строка файла с ↓ скачивает его, затем явное сохранение на устройство. Ограничения/права протокола прежние.

Менеджер показывает «Это устройство» и «Удалённый компьютер» рядом; на узком/низком экране — вкладки. Выделение файла не запускает передачу: действуют «Отправить →» и «← Скачать». Локальный системный выбор поддерживает несколько файлов для списка, но передача идёт по одному. Chromium с `showDirectoryPicker` дополнительно открывает только выбранную пользователем папку в режиме `read`, позволяет переходить внутри неё без рекурсивного сканирования; неподдерживающие браузеры используют выбор файлов. Сохранение скачанного файла всегда выполняется системным механизмом браузера, не автоматически в выбранную локальную папку. Дескрипторы папок/File и выделение — только RAM до закрытия; поздний ответ picker/чтения после закрытия игнорируется. Выбор локального файла сохраняется при навигации на удалённой стороне, чтобы выбрать целевую папку.
